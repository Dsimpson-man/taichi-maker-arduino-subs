## 本节要点

- 认识 Node-RED 中的 MQTT 功能节点：`mqtt in` 用于订阅主题，`mqtt out` 用于发布信息
- 学会排查红三角报错"无效的属性 broker"，并新建一个 MQTT broker 服务端配置
- 掌握服务端配置的各个项目：服务端地址与 1883 端口、客户端 id 编号规则、安全认证、出生消息 / 关闭消息 / 遗嘱消息
- 完成 `mqtt out` 与 `mqtt in` 节点的设置与部署，配合 `inject` 节点与 `debug` 节点验证订阅与发布
- 安装 Node-RED 控制台（dashboard）节点：在"节点管理"中搜索并安装 `node-red-dashboard`
- 学会使用 `button` 节点建立打开 / 关闭 LED 的按键，并设置分组（group）与标签页（tab）
- 学会使用 `text` 节点把控制指令显示在控制台界面中，并在 dashboard 侧栏中调整元素排列顺序

## 正文

大家好，欢迎收看零基础入门学用物联网教程。在上节课的教程里面，我们学习了 Node-RED 软件的基本操作，那么在这节课里，我们将一起来学习如何使用这个 Node-RED 软件来搭建一个简单的 MQTT 物联网控制台。

首先我们先来了解一下如何使用 Node-RED 软件来实现 MQTT 的订阅和发布。我们首先要找到 Node-RED 软件中 MQTT 的功能节点，这个功能节点请看，我鼠标拉动这个滚动条，我们来到这个"网络"这部分，这部分的节点都是 MQTT 的网络功能节点。其中最上面这两个，这两个 `mqtt in` 和 `mqtt out` 都是用来实现 MQTT 通信的：上面这个 `mqtt in` 是用来订阅 MQTT 主题的，这个 `mqtt out` 则是用来发布 MQTT 信息的。

### 一、从 mqtt out 节点入手：部署报错排查

首先我们来看一看这个 `mqtt out` 这个节点，这个节点我刚才说了，它是用来发布 MQTT 信息的。我们把它拖到我们的工作区域中来，然后请注意，我们要找到一个信息让这个信息发布出去，就拖动一个 `inject` 节点，这个节点我们上节课给大家讲过，通过点击前面的这个按钮我们就可以产生一个测试信息。好，让这个测试信息到哪里去呢？我们把它连接到 `mqtt out` 节点上。

连接好以后，接下来我们就要部署一下，不然的话这些节点是不会发挥作用的。我们来点击部署，这个时候我们看到这个软件给我报错了，什么报错呢？它说现在这个工作区域中包含一些未能正确配置的节点：流程 1，`mqtt out`，你确定要部署吗？

如果您看到这个对话框的话，那么说明您现在的这个工作区域中某些节点可能设置存在一些问题。那在这种情况下，你应该按照它这个提示来找一找。请看它这里提示是"流程 1，`mqtt out`"这个节点，那我们先把这个取消掉。我们的流程一正是我们这个工作区域中的这个 `mqtt out` 这个节点有问题，它有什么问题呢？

请您注意，在这个节点上有一个红色的三角，我把我的鼠标挪到这个红色三角上以后，请看这里写着一个无效的属性，冒号 broker。什么意思呢？在这里有个 broker，它正是我们这个服务端的意思。那它这里无效的属性 broker，代表我们这个 MQTT 服务端没有进行正确的设置，我们需要把这个服务端设置好以后才能够实现 MQTT 通讯。

所以以后您在使用 Node-RED 的时候，看到节点上出现红色三角，就可以把鼠标挪过去看一看它的提示信息，通常它都会明确地告诉您是哪一个属性出了问题。这个红色的三角是 Node-RED 用来提示节点配置不完整的标志，只要把它提示的属性补齐，红色三角就会消失。

### 二、新建 MQTT broker 服务端配置

那怎么设置呢？我来双击这个 `mqtt out` 节点，在弹出这个对话框里面请看，在上面这里服务端这地方，它这里没有任何的设置，需要我这里添加一个新的 MQTT broker。那么我怎么来添加呢？请看我要点击右边这里有一个像铅笔那个图标，我点击它，然后接下来我就要输入这个我的 MQTT 服务端的相关信息了。

我使用的是巴法云物联网社区版的这个信息。那么首先我在这里输入的是巴法云物联网社区版的这个网址，是 `bemfa.com`，端口 1883，默认的，不用管它。我们不使用 TLS 通讯，这个协议标准就使用这个 3.1.1 版本的，默认的就可以。

这里要输入这个客户端 id，那我在这里输入的客户端 id，我设的是 `iot_user` 下划线四，下划线 ID。那这里为什么要写这个数字四呢？原因是：我们这个数字一给 MQTT.fx 软件用了，二呢给 ESP8266 用了，第三呢是给巴法云物联网手机应用用了，这个四就是我们电脑端的这个 Node-RED 软件来使用了。好，这里就是 `iot_user_4_ID`，这是我的客户端 id。

前面我们在 MQTT 客户端软件、ESP8266 开发板、手机应用这些内容中，都反复强调过客户端 id 不能乱填这个规则，同一个服务端下面每一个设备的客户端 id 必须是唯一的，所以我们用编号来区分不同的设备。在巴法云社区版中，客户端 id 的组成方式是：以您的用户名开头，然后加上一个下划线，再加上设备的编号，最后再加上一个下划线和 id 这几个字符。

接下来请看这里这个 keep alive，60 秒，默认的，不用管了，然后"使用新会话"，这里都是有默认的。好，接下来我点击这个"安全"这个地方，在这里我将要输入我客户端认证的用户名和密码，用户名是 `iot_user_4`，密码呢 `password`。

写完以后，"消息"这里的内容可填可不填，那么为了保持知识的完整性，在这里我给大家讲一讲这些内容是什么。我们在这个消息设置这一部分，一共有三组消息可以设置：第一组是"连接时发送的消息"，也就是出生消息；第二组是"断开连接前发送的消息"，也就是关闭消息；第三组是"意外断开连接时发送的消息"，也就是遗嘱消息。

首先我们来看最上面这个"连接时发送的消息"，也就是出生消息，并且这里让我输入一个主题，并且在这里输入内容。那么为了讲解方便，我先把我这里这个主题先写上，然后我再给你讲讲我这么做的目的是什么。

请注意我的屏幕，首先我输入 `iot_user`，这是我的个人级别，必须要加在这里，作为我这个宝塔认证的机制，其他人不能使用的，只有正确输入密码、用户名以后才能够订阅这个级别下面的信息。我输完这个以后，接下来写一个 `node_red`，然后接下来再输一个 `connect`，这个就是出生消息的主题。接下来我再写出生消息的内容，我写一个 `node-red connected`。

说完这个内容以后，是不是有些朋友已经大概猜到它们的作用是什么了？那接下来我给你讲一讲。当我们这个装 Node-RED 软件这台电脑成功地通过物联网连接到了服务端以后，他马上做的第一件事情就是要向这个主题，你看就这个 `iot_user/node_red/connect` 这个主题，发布一条内容，这个内容具体的信息就是 `node-red connected`。那么这么做的目的就是：可能有些设备它需要获取到当前我们这个 Node-RED 的电脑它是不是连接到服务端了，如果有需要获取这个信息的话，那么其他的物联网设备就可以订阅这个主题，那么一旦我们这个 Node-RED 连接到服务端以后马上就会发布这个信息，然后其他设备就会马上知道当前装 Node-RED 软件的电脑已经连接到服务端了，就这么一个作用，这就是出生消息的作用。

好，那关于出生消息的主题和内容设置好以后，关于它这个"保持"以及这个 QoS，我就默认不用去修改它。那么接下来我们来看这个"关闭消息"，也就是断开连接前发送的消息。关闭消息正好和这个出生消息是反过来的，我在这里同样还是使用这个主题，就这里这个，你看我鼠标高亮这个主题，我把它复制，然后把它粘贴到这里，同一个主题。但是内容不一样，这里我是 Node-RED connected 那英文的，是 Node-RED 连接上了；那么这里我写上 `node-red disconnected`，那就是 Node-RED 断开连接了。

那这里它的作用是什么呢？可能你已经猜到了，出生消息是 Node-RED 软件这个电脑连接到服务端以后马上就要发出这个消息，关闭消息自然就是当我们这个 Node-RED 软件它正常地和服务器断开连接了，注意我这里强调的是正常断开，正常断开以后，那么它就会向这个主题发布一条消息，另外订阅这个主题的其他设备就知道：当前这个 Node-RED 软件正常地断开了和服务端的连接了。这个就是关闭消息的作用。这里保持和 QoS 我依然不去修改它。

继续往下看，请看这里这个"意外断开连接时发送消息"，后面的几个 will 消息，will 消息是什么，大家记得吗？是遗嘱消息。遗嘱消息的作用是什么呢？我以前给大家讲过，这里不给大家重复了。简单地说，它是在我们的设备意外断开连接的时候，由服务端代替这个设备发布出来的消息，这样其他的设备就能知道这个设备是非正常掉线了。

那么这里我这个主题我同样的还使用相同的主题，皮啊，paste，相同的主题，出生消息、关闭消息、遗嘱消息都用相同的主题。那么内容我就不一样了，不然的话就混了。这个遗嘱消息我写 `node-red lost`，它这个是意外的断开连接的时候，就会向这个主题发布这个消息。那么这个就是关于这个消息的设置了。

这样一来，订阅了 `iot_user/node_red/connect` 这个主题的其他设备，就可以通过这个主题上收到的内容来判断当前 Node-RED 这台电脑的状态了：收到 `node-red connected` 就说明它上线了，收到 `node-red disconnected` 就说明它正常断开了，收到 `node-red lost` 就说明它是意外掉线了。这就是出生消息、关闭消息和遗嘱消息配合起来的作用。

连接设置好了，安全设置好了，消息设置好了，接下来我们就要给这个新的配置起个名字了。这起个什么名字呢？我在这里写上叫"巴法云物联网社区版"。然后点击这里，注意，全部做好以后点击这里"添加"，添加以后请看这里就会显示"巴法云物联网社区版"这个连接配置了。那么如果我在这里出现了一些问题，我想修改一下怎么办呢？我同样的还可以选这个小铅笔的图标，然后就可以进行相应的修改了。那我先不修改，一会我看看能不能连上，连不上的话我再改。

### 三、设置 mqtt out 节点并部署

我先回过头来，接着往下看。我们选中当前这个服务端是巴法云社区版，就刚刚设置好的服务端，接下来我来填入我要订阅的主题的名称：`iot_user` 这个模式，然后 `led_KZ`。还记得这个主题的作用是什么吗？我之前课程给大家讲过，它是用来控制一个 ESP8266 开发板上的一个 LED 点亮熄灭的，我们同样还是用这个主题。后面这个 QoS 我们就不再进行设置了，你感兴趣可以自己来进行设置，默认的不理它了，保留不用去动它。

接下来我们就可以给我们这个 `mqtt out` 这个节点起个名字了，这个名字的作用就是为了便于我们识别出这个节点，我们就给它起一个名字叫做 LED 控制 MQTT 节点。那么全部都做好以后，我点击完成，我们看到刚才的节点这个名字变成 LED 控制 MQTT 节点了。到这里我们这个节点就把它设置完整了，不过现在我们这个节点还没有连接到服务端上，怎么才能让它连接服务端呢？我还要点击这个"部署"。在点击完部署以后我们可以看到，这里显示出来一个绿色的图标，旁边写着"已连接"，说明我们这个节点已经成功地连接到 MQTT 服务端了。

那我们如果想向这个节点发布消息怎么做呢？自然就点击这个蓝色的按键。点击这个按键以后，我们可以看到上面显示的成功注入时间戳，那么这个时间信息就把它发布到 LED 控制 MQTT 节点了。目前我们暂时看不到什么效果，因为我们现在只有一个发布消息的 MQTT 节点，发布了消息以后没有节点去接收和显示它，所以看不到它到底发出去了什么。那要想看到我们发布出去的信息，就要再加一个订阅的节点。

### 四、添加 mqtt in 节点与 debug 调试节点

接下来我们再来加一个订阅 MQTT 消息的节点，怎么加呢？请看这里就有一个 `mqtt in`，这个就是订阅 MQTT 消息的节点。我们把它拖到我们的工作区域来，然后我双击这个节点，接下来我就来设置这个 `mqtt in`，也就是订阅 MQTT 消息的节点。我们选择这个服务端，同样还是巴法云社区版，刚才我们设置好的这个服务端；那么主题呢我们订阅刚才我们设置好这个 `iot_user/led_KZ`。注意，这是刚才我们使用这个主题 `led_KZ` 控制 LED 的主题。QoS 我们就不动它了，输出也不去管它。名称呢我们还给它起个名字，这个起名叫做 LED 控制 MQTT 节点，订阅这个 LED 控制 MQTT 节点。然后我点击完成。

设置好以后这里出现蓝色的方块，说明我们还没有把它部署。不过在部署之前，我们需要把这个获取到的信息能够通过屏幕显示出来，怎么才能让屏幕显示这个信息呢？我们找一个 `debug` 这个节点，好了，然后我们把这个刚才设置好的这个 `mqtt in` 的这个节点，把它获取到的信息把它输送给，注意这里给这个 debug 节点。这个 `debug` 节点就是我们所说的调试节点，它接收到的信息会显示在 Node-RED 右侧的调试窗口里面，方便我们观察节点之间到底传递了什么样的数据。做好这些工作以后，接下来我就可以进行部署了，我点击部署。我们可以看到刚才我们这个 `mqtt in` 这个节点它也已经成功地连接到服务端了，这里显示绿色的已连接。

那么我在这里打开我这个调试窗口，然后我先把这些比较乱的信息删掉。删掉完以后，我接着就来，注意点这个时间戳这个按键，我一点，没有问题，通知时间戳的点击，我把这个当前的这个系统时间发布到这个 LED 控制节点上去，那么这个 LED 控制节点它发布信息以后呢，我们在这里这个 `mqtt in` 这个节点它是获取到了发布来的这条消息，并且显示在我们的屏幕中。好，我们再来一下，又出现了。

不过这个消息还不能控制我们这个 LED 点亮和熄灭，那我来修改一下，我们来双击一个时间戳节点，我让它把发布的这个消息内容不再是时间信息了，这个时间信息控制不了 LED，我把它改成数字，改成数字一，然后点完成，再点部署，把这个消息给删掉。我观察，接下来我来摁一下一，好，没有问题，我一按这个按键一，这个数字就会通过这个 `mqtt out` 节点发布到这个主题了，同时我们这个订阅了相同主题的这个节点也会马上收取到这个数字一，并且把这个数字一显示在我们的电脑屏幕中，这就是我们现在所编程的这一系列的节点它们的工作内容。

那么现在我们只能是打开 LED，我还能熄灭 LED，我们怎么来熄灭 LED 呢？我再增加一个 `inject` 节点，那么在这个 `inject` 节点它所输出的信息内容呢，我们把它输出到说到这里，是不是这个 `mqtt out` 节点上去，好，那么我们想让它输出什么内容呢？同样属于数字，数字零，因为数字一是打开 LED，数字零就是关闭 LED。好，让我来点击部署。

好了，那我们现在有两个节点了，这个节点是 1，摁，马上就收到数字一；那么这个节点是 0，摁，马上就收到数字零。通过这两个节点我们就可以控制 ESP8266 开发板上的 LED 点亮熄灭了。您可以根据我这个测试试一试，是不是能够控制您自己这个 ESP8266 开发板上的 LED 点亮熄灭，如果可以的话，太棒了，接下来我们就可以看后面内容了。

### 五、安装 Node-RED 控制台（dashboard）节点

后续内容是什么呢？这课程中我给大家讲过，我们这个 Node-RED 软件是可以建立 MQTT 控制台的，到现在我们都是只通过这些节点的按键来演练和熄灭 LED，并没有使用控制台。那下面我给大家介绍如何来搭建这个 MQTT 控制台。

要搭建 MQTT 控制台，就要使用 Node-RED 软件的控制台节点了，但是这个控制台节点没有预装到这个 Node-RED 标准软件中，需要额外的安装。那么怎么来额外安装更多的 Node-RED 节点呢？接下来我给你演示一下。

请注意屏幕，首先我们看这个屏幕右上角，这里有三条横线，我们来点击它，这时候我们就可以看到 Node-RED 软件的主菜单呈现在我面前了。我们将要选择这里这个"节点管理"这个选项，我们点击它，点击它以后就会弹出一个新的界面了。在这个界面中请看，这里有一个"安装"的标签页，我们点击这个安装，然后请看，在这里这个搜索栏，我们在这里将搜索我们将要安装的这个节点的名称，这个节点名称它是英文的，请注意我在屏幕上输入的这个英文信息不要错任何一个字符。请注意我将要输入 `node-red-dashboard`。
