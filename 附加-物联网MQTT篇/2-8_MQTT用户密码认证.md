## 本节要点

- 用户密码认证指的是客户端连接服务端时需要提供用户名和密码，这个认证是可选的，不是所有客户端都必须提供
- 用户名和密码通过 `CONNECT` 数据包中的 `username` 和 `password` 两个字段传递，服务端校验通过才允许连接，否则拒绝连接
- 用户密码认证有两大作用：一是保护自建服务端不被陌生人随意使用，二是让服务端能够识别客户端属于哪个用户，从而分配专属的 MQTT 资源
- 使用燃也物联服务端时，可以用测试用户 `testuser` / 密码 `ranye-iot` 来体验认证机制
- 燃也物联服务端对测试用户可用的主题有限制：只能订阅和发布以 `testuser/` 开头的主题
- 在 ESP8266 客户端中实现用户密码认证，只需在 `connect()` 函数中在客户端 ID 之后依次提供用户名和密码三个参数
- 本节是 MQTT 协议基础这一章的最后一节，视频后半部分对整章知识点（QoS、保留消息、心跳、遗嘱）做了系统总结

大家好，欢迎收看零基础入门学用物联网教程 MQTT 篇。在今天的课程中，我们一起来学习 MQTT 用户密码认证方面的知识。

我们这里所说的用户密码认证，指的是客户端在连接服务端的时候需要提供用户名和密码。那么这个用户名和密码实际上是可选的，并不是说所有的客户端在连接服务端的时候都要提供这个信息，只是在有些情况下需要提供。那么在什么情况下需要提供这个信息呢？我们知道，在我们这个教程中一直使用的是燃也物联的服务端，这个燃也物联的服务端是不需要我们提供用户名和密码的，直接就可以连接上。但是在有些情况下，比如说我们个人搭建了一个专门属于我们自己的 MQTT 服务端，为了保护我们这个服务端不被陌生的人所使用，我们可以为服务端增加一个用户名和密码的保护机制。这样的话，客户端在连接服务端的请求中正确输入用户名和密码以后，才能够连接上我们自己的 MQTT 服务端。

那么客户端是怎么向服务端来提供这个用户名和密码的呢？正是通过 `CONNECT` 数据包。请看，在 `CONNECT` 数据包中有 `username` 和 `password` 这两个信息内容。我们这个示例中的 `username` 就是用户名的意思，在这里这个示例中的用户名是 `hans`；下面这个 `password` 密码就是这行字符。通过在 `CONNECT` 数据包中添加这两个信息，就可以实现这个用户名密码的认证机制了。服务端在接到这个 `CONNECT` 数据包的时候，它就会检查一下这里的用户名和密码，如果正确的话，就允许这个客户端来连接，否则的话就会拒绝客户端连接。这就是用户名密码的一个基本工作流程，还是比较简单的。

事实上，这个用户名密码机制除了我刚才说的可以起到保护服务端不被陌生人使用这个功能以外，还有一个功能。什么功能呢？就是服务端可以利用这个用户名和密码这个信息内容来管理客户端。通常情况下，对于 MQTT 服务端来说，有可能有很多用户在同时使用，那么对于这些不同的用户来说，他们都有各自的客户端。这些各自私人的客户端可能会使用一些私人的 MQTT 资源，比如说有一些 MQTT 主题专门属于某一个用户，这些 MQTT 主题只能是这个用户的客户端才能够使用，别人是不能用的。

比如说我们这个例子中，在这里这个 `username` 是 `hans`，也就是汉斯先生。他的这个客户端在连接这个服务端的时候，当服务端看到这个客户端发来的数据包中体现出来这个用户名是 `hans`，并且它提供的密码是正确的话，那么服务端就知道这台客户端设备是属于汉斯先生的。那么这汉斯先生他就可以使用我们这个服务端上的一些专门属于他自己的 MQTT 主题或者其他资源。正是通过这个机制，我们的服务端就知道某一个客户端它属于哪个用户，这个是用户名密码的另外一个作用。

那我们开始。首先，我们这章刚开始的地方，我们给大家讲解了 QoS 服务质量等级这个概念。就这个服务质量等级，它有三个非常核心的知识：第一个就是 QoS 为零的时候最多发一次，QoS 等于一的时候最少发一次，QoS 等于二的时候保证收一次。这三个概念的具体含义，我不知道你还有没有印象，如果你没有印象的话，可以回顾一下，到这里好好看一看，这是最核心的概念。

我还想再强调一下这个服务质量等级它的实际意义。这三个等级从零到二，可靠性越来越高，但同时它们所消耗的网络资源和通讯开销也是越来越大的。所以在实际应用的时候，我们并不是说等级越高就越好，而是要根据我们的实际需要去选择：一般来说，像普通的传感器数据上报这种允许偶尔丢一两条的信息，用 QoS 0 就足够了；如果这个信息比较重要，不希望丢失，可以用 QoS 1；如果这个信息不仅不能丢失，而且绝对不允许重复，那就需要用 QoS 2。这也是我们在学习这一章的时候需要特别注意的一个观念，就是服务质量等级要按需选择。

那么如果要想使用这个服务质量等级大于零的话，除了刚才我们说的这个对 QoS 进行设置以外，同时还要在客户端连接服务端的时候对这个 clean session 进行设置。clean session 是在 `CONNECT` 数据包中有专门一个信息，就是 `clean session`，要把它设置成什么呢？如果要是 QoS 大于零，使用一级、二级的话，就要把这个地方使用 false。另外，这个服务质量等级它存在一个降级的概念。怎么就叫降级呢？发布消息和订阅消息的时候，它们谁更低就用哪一个级别来实现这个信息的发布。这个关于降级的知识也是非常重要的，所以您要到这个地方好好加强，看懂听明白才能正确使用这个服务质量等级。
