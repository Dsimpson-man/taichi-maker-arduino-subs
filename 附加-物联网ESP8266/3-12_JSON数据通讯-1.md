## 本节要点

- ESP8266 的 JSON 数据通讯有两种模式：一种是开发板之间通过 WiFi 局域网通讯，另一种是通过互联网与网络服务器通讯。
- 服务器响应给客户端的 JSON 信息中包含三个名值对：`info`（固定的字符串信息）、`digitalPin`（三个数字引脚的实时状态）以及模拟引脚的实时读数。
- 服务器端程序把第一、第二、第三和 A0 引脚设置为输入上拉模式，通过 `digitalRead()` 读取实时状态，再用 `String()` 转换成字符串拼接到 JSON 响应字符串中。
- `return` 返回的字符串是通过响应体发送给客户端的，而响应头中的类型说明要告诉客户端响应体是一段 JSON 信息。
- 响应头与响应体之间用一个空行分隔，这是定位响应体起始位置的关键。
- 客户端通过 `readStringUntil('\n')` 读取服务器响应信息的第一行，也就是响应状态行；只有确认状态码是 200 OK，才继续后续的解析工作。
- 用 `find()` 找到响应头的结尾后，剩下的 stream 数据就是响应体，也就是需要解析的 JSON 信息。
- `parseInfo()` 接收 `WiFiClient` 类型的参数，把 `client` 对象交给 ArduinoJson 解析，取出的值需要用 `as<String>()`、`as<int>()` 等函数做类型转换。
- 数组中元素靠序号访问且序号从 0 开始，因此第三引脚对应的下标是 2；取出的引脚状态用于控制客户端 LED 的点亮与熄灭。
- 服务器端也可以借助 ArduinoJson 在线工具自动生成代码，用 `serializeJson()` 建立 JSON 信息，并在 `capacity` 的原有计算基础上再增加 140 以提升程序稳定性。
- 无论使用解析还是生成 JSON 的代码，都不要忘记在程序开头 `#include <ArduinoJson.h>`，否则编译会出错。
