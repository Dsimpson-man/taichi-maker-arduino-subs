## 正文

大家好。在这节课里，我们要用 ESP8266 NodeMCU 来搭建一个网络服务器。应该说网络服务器是一个比较宽泛的概念，具体到我们这节课，要搭建的是一个可以提供网页服务的网络服务器。讲到这儿可能有朋友会好奇：这个网页服务器的意义是什么呢？一方面，我们可以通过服务器所建立的页面来控制 NodeMCU 开发板；另外一方面，我们也可以通过服务器所建立的页面来获取当前开发板各个引脚的状态。可能这么说还有点抽象，接下来我给您详细地讲一讲。

首先请您回顾一下网页服务器的基本工作原理。假设现在我们通过电脑打开浏览器，想要访问太极创客的网站首页，这时候我们在浏览器的地址栏里输入了太极创客的网址，这个请求就会通过互联网发送到太极创客的网站服务器上，处理完以后，网页内容也会通过互联网返回到我们的电脑中。当然了，实际的过程要比刚才我所讲述的复杂得多，这里只是把这个过程做了一个简化。

接下来就要请出我们这节课的主角了，也就是我们的 NodeMCU 开发板。在讲解后续的知识之前，我想先提醒您一下，请看这个示意图。我们这个示意图中，NodeMCU 开发板是以无线终端的形式来工作的，换句话说，NodeMCU 它是可以连接到我们的 WiFi 路由器所建立的网络中的。同时在这个 WiFi 路由器所建立的局域网中，还有其他的网络设备，比如这里是我的电脑，这里是我的手机，这些设备都可以通过我们的 WiFi 路由器来实现网络通讯。

同时请您注意，我们这个 WiFi 路由器它是不是连接到互联网上，和我们这节课后续讲解的知识没有什么关系。为什么这么说呢？原因是在我后续给您讲的示例中，我们所访问的网站服务器并不是互联网上的某一个网站服务器，而是什么呢？而是在我们这个 WiFi 路由器所建立的局域网中的这个 NodeMCU 开发板它所建立出来的这么一个网站服务器。也就是说，我们现在所要访问的这个网站是建立在 NodeMCU 开发板上的。

那么现在假设我要用我的电脑来访问太极创客的网站首页，同样的，我们的电脑也会产生一个请求，会通过 WiFi 路由器发送到 NodeMCU 这个网站服务器上；当这个网站服务器处理完以后，同样的也会通过 WiFi 路由器最终传递到我们的电脑中，然后我们的电脑就可以打开这个网站的首页了。在这儿可能大家已经意识到了，整个这个过程中，只是我们这个 WiFi 所建立的局域网内设备之间的通讯，因此这个 WiFi 路由器是不是连到互联网上，和我后续的讲解没有什么关系。

接下来我们就来看看这节课主要讲解的示例程序的具体内容。请来到我们太极创客网站关于零基础入门学用物联网这个教程的目录页面中，在这个目录页面里有一个「用 C++ 的方式来开发物联网」，在这个链接里面，上节课我主要给大家讲解的是物联网开发的基础，这节课我们要着重讲解 NodeMCU 的网络服务器功能。在这个打开的页面中我们可以看到，我们这节课将主要讲解三个主题：第一个主题是如何使用 NodeMCU 来建立一个基本的网络服务器；第二个是如何通过网络服务来实现 NodeMCU 的基本控制；第三个是如何通过网络服务来将开发板的引脚状态显示在网页中。我们首先看第一个主题，也就是如何建立基本的网络服务器。

在这个页面中请看，这里就是我们将要讲解的示例程序了。接下来我们把这段示例程序复制并粘贴到我们的 Arduino IDE 中。好，现在您在屏幕上看到的这个程序就是刚刚复制粘贴好的代码了，我们来看看这个程序的具体内容。首先我们来看程序刚开始的部分，在这里我们可以看到程序一共 `include` 了三个头文件，其中前两个 `ESP8266WiFi` 以及 `ESP8266WiFiMulti` 这两个头文件所涉及的内容，我们在之前的课程中给大家讲过；第三个这里 `ESP8266WebServer` 这个头文件，它所涉及的内容将是我们后面这个程序中主要讲解的重点。

好，具体内容我们接下来给大家讲。我们先往下看，首先看第一句，这第一句的程序内容我在上节课中给大家讲过了，它的主要作用就是允许我们可以连接多个 WiFi 网络，这里是建立这么一个对象。好，它具体的使用是在 `setup` 函数这里，在这一部分，那么这块我就不给大家再重复讲解了。我们来看后面这条语句，这条语句需要好好给您讲一讲了。请看，整条语句刚开始的地方是 `ESP8266WebServer`，这个是不是大家看着有点眼熟？没错，在程序刚开始 `include` 头文件这个地方有相同的字样。这条语句的作用是要建立一个网络服务器这么一个对象，这个网络服务器对象它的对象名称请看，是后面这里的 `server`。

我们一看到，这个对象呢，是带一个参数的，参数就是括号里面这个 `80`。这个 `80` 的含义就是我们这个网络服务器在应对网页请求的时候，它使用哪一个端口。可能有朋友不是很理解，这儿我给大家讲一讲这个网络服务器端口的概念。要解释端口的概念，我们还要从网页服务器的地址说起。我们在浏览器中访问一个网页的时候，输入的地址是由几部分组成的，前面是协议，然后是服务器的地址，地址后面可以跟一个冒号，冒号后面就是端口号。

我们再补充一点，就是关于这个 HTTP 协议。我们平时访问网页所使用的这套规则，叫做 HTTP 协议，也就是超文本传输协议。它规定了浏览器和服务器之间该如何「说话」：浏览器要发什么样的格式的请求，服务器要回什么样格式的回应。我们在前面讲过的请求方法 GET 和 POST，就是这套协议当中规定的内容。GET 一般是用来向服务器索取信息的，比如我们打开一个网页，就是请服务器把网页内容给我们；POST 一般是用来向服务器提交信息的，比如我们在网页上填了一个表单然后点提交，这就是 POST。这个区别在后面我们做控制实验的时候会看得非常清楚：打开页面是 GET，按下按键是 POST。

好，下面我们来看一个具体的例子，这样更容易理解。我们来打开浏览器，在地址栏中输入太极创客的网址。可能大家注意到了，平时我们访问网页的时候一般是不会写端口号的，为什么可以不写呢？因为浏览器有一套默认的约定：如果我们访问的是网页服务，那么默认使用的就是 `80` 这个端口，所以可以省略不写。也就是说，我们平时输入网址按下回车，浏览器实际上是自动帮我们加上了 `80` 这个端口。

这里我们可以把端口理解成一栋大楼里的房间号。IP 地址相当于这栋大楼的地址，它告诉我们网络数据要送到哪台设备；而端口号相当于房间号，它告诉我们数据要送到这台设备上的哪一个服务。同一台服务器上可以同时开着很多个服务，比如网页服务、文件传输服务、邮件服务等等，它们各自占用不同的端口，互相之间不会打架。网络数据到了这台设备以后，就是靠端口号来判断这份数据应该交给哪一个服务来处理的。所以我们在建立网络服务器对象的时候写 `80`，实际上就是在说：我们这个开发板要在 `80` 号这个房间门口提供服务，浏览器按默认习惯找过来的时候，就能直接找到我们。

那接下来我们来做一个验证，看看端口是不是真的起作用。我们在网址后面加上冒号，然后输入 `80`，也就是明确地告诉浏览器我们要访问 `80` 这个端口，然后按下回车，可以看到网页正常打开了。这说明 `80` 端口确实是提供网页服务的端口。那下面我们来试试别的端口，我们还是用太极创客网站这个服务器，同样输入网址，刚才我们说到后面输入这个冒号，是输入 `80` 这个端口，这次我们不输入 `80` 了，我们输入 `81` 这个端口，也在冒号后面，我跟一个 `81`。我们可以看到这个网站半天是没有反应。原因就是，当我们想要用浏览器访问服务器的 `81` 这个端口的时候，服务器是不给我们提供这个服务的，为什么呢？因为服务器提供网页服务的端口是 `80`。可以看到现在这个网页是无法打开的。

我们还恢复回来，把这个 `80` 端口再恢复回来，没有问题，很快这个网站就打开了。通过刚才这个讲解我们可以看到，这就是为什么我们在写这段程序的时候，在建立一个网络服务器对象、提供网页服务的时候，要在这里输入 `80` 这个数字，原因就是便于我们浏览器访问我们的网络服务器。

刚才花了这么多时间来给大家讲解网络服务器的端口概念，原因呢就是端口概念是一个非常重要的概念。现在我们提供的是网页服务，后面我们可能用我们的 NodeMCU 开发板来提供其他的服务，这时候我们就要指定不同的端口来提供不同的服务，这一点请大家务必要记住。

我们继续往下看，在程序中这里来到了整个程序的 `setup` 函数了。`setup` 刚开始的第一句是启动串口通讯，不用浪费时间了。后面这个之前我给大家讲过了，是连接 WiFi 所用的语句。再往后这个 `while` 循环语句也是之前给大家讲过的，这段循环语句的作用就是让 NodeMCU 开发板在没有把网络连接成功之前一直在这里等待，连接成功以后才会执行后面的一句。后面一句是什么呢？就是通过串口通讯输出我们 NodeMCU 所连接的这个网络是哪一个，以及这个 NodeMCU 它的 IP 地址是什么。这个 IP 地址的作用是什么呢？我们后边在访问这个 NodeMCU 开发板的时候需要用到的，这个知识我后面再给大家讲。我们先继续往下看。

请看，在 `setup` 函数后面这部分程序，这部分程序可以说是我们整个程序非常重要的部分，请大家务必要认真去听。我们可以看到这里一共有三条语句，这三条语句都有共同的特点，前半部分请看，都是针对我们 ESP8266 服务器这个对象的，这个对象在哪呢？我们刚刚给大家讲过，在整个程序中我们是在这里建立了这么一个网络服务器的对象。那么后面请看，我们还回到第三条语句来，后面这里分别调用了三个不同的库函数，这三个库函数是在哪里定义的呢？是在 `ESP8266WebServer` 这个库里面所定义的。

说到这里我们顺便讲一讲「对象」这个概念。我们在程序里写 `ESP8266WebServer server(80)` 这一句，实际上做的是这样一件事：按照 `ESP8266WebServer` 这个库所定义的模子，造出一个实实在在的服务器出来，并且给这个服务器起个名字叫 `server`，同时告诉它要使用 `80` 这个端口。这就好比我们照着图纸造了一台机器，并且给它编了个号，以后我们要操作这台机器，只要喊它的名字 `server` 就可以了。所以我们后面看到 `server.begin()`、`server.on()`、`server.handleClient()`，都是在指挥同一台机器做不同的事情。这种写法在 C++ 里叫作面向对象，我们在后面的课程中会越来越多地碰到。

我们还回来，那么这三个库函数各自都有不同的功能，我们看第一个，这个库函数 `begin`，它做的就是来启动这个网络服务器的功能。换句话说，通过这条语句，我们的 NodeMCU 开发板将会通过它的 `80` 这个端口开始提供网站服务了。那么我们回到这里，这个网站服务的具体内容是什么呢？就是后面这两条语句所定义的了。我们看第一条语句，这第一条语句是 `on` 函数，后面请看这里有两个参数，这两个参数都非常重要。我们先看第一个参数，这也是一对双引号，里面有一个斜杠，这个斜杠的作用就是说，当我们浏览器想要访问的是这个斜杠这个页面的时候，那么它是告诉 NodeMCU 开发板，你将会通过我们程序中的哪一个函数来处理我这个访问。

可能在这里有朋友已经完全糊涂了，什么斜杠的页面，还有什么网络服务的函数，这都是什么呢？我一点一点给你讲。首先这个斜杠的页面是什么呢？默认的情况下，如果我们的浏览器所访问的首页就是这个斜杠的页面。也就是说，当我们的浏览器想要访问的是这个网站的首页的时候，NodeMCU 开发板可以使用这个叫做 `handleRoot` 的函数。handle 是处理，root 是根，也就是处理根，什么处理根啊？通常这个首页都是放在根目录下。好，请看这里，这里就是我们这个 `handleRoot` 函数的具体内容了，不过这个函数的内容我一会儿再给大家讲解，你现在只要记住一点，就是我们这个程序的后面这里有一个叫做 `handleRoot` 这么一个函数，`handleRoot` 这个函数的作用就是来提供首页信息的。

那么 NodeMCU 开发板在什么时候才需要为浏览器提供这个首页信息呢？自然就是浏览器在访问首页的时候。我最后再给大家总结一下，这里这个 `on` 函数的作用就是，当浏览器想要访问首页的时候，这时候 NodeMCU 它这个网站服务器是可以通过调用 `handleRoot` 这个函数来提供首页信息的，这就是我们现在这个 `on` 函数的作用。目前我们这个服务器只能提供一个页面，也就是网站的首页，所以我在这儿只有一条语句，也就只调用了一次 `on` 函数。假如我们这个服务器是有多个页面的话，我们可以提供多个 `on` 函数，并且在后面告诉这个 NodeMCU，当浏览器访问不同的页面的时候可以通过调用哪些函数来处理。

我们继续往下看。好，下面这里就是刚才我说的 `handleRoot` 这个函数了，我们来看一看这个函数里面的具体内容。请看这里第一句，`server.send`，这个 `send` 就是发送的意思，前面依然是那个网络服务器的对象，后面这个 `send` 函数是 `ESP8266WebServer` 这个库里面的一个库函数，它的作用就是向浏览器发送信息。这个 `send` 函数我们需要好好讲一讲，因为后面我们还会经常用到它。请看它括号里面有三个参数，这三个参数我们一个一个来看。

第一个参数是 `200`，这个 `200` 是一个服务器的响应状态码，它的含义就是要告诉请求这个信息的客户端，比如说我们现在是用浏览器来请求网站的这个页面，那么通过这条语句，NodeMCU 开发板就会向这个浏览器首先发送 `200` 这个状态码。浏览器收到这个 `200` 状态码以后就知道，OK，服务器已经找到了我要找的信息了。那信息的具体内容呢？就是后面这部分。

首先第二个参数是要告诉浏览器，我接下来要发送一段网页的数据信息，这个数据信息它是属于什么类型、该怎么来处理这个数据信息。那么具体类型是什么呢？请看是 `text/plain`，也就是说我们接下来发送的信息是一段纯文本的信息。我怎么知道它是纯文本信息呢？因为这里说得很明白，text 是文本，后面 plain 是纯的，纯文本就是 `text/plain`。讲到这儿可能有朋友说，那是不是还有别的文本信息呢？可能会有别的文本信息，比如常见的还有，请看，还有比如说像 `text/html`，这也是一段文本信息，那这段文本信息将是一段 HTML 网页代码。不过在这儿我还是恢复回来，因为我们接下来这个文本信息并不是网页代码，它这个文本信息就是纯文本信息。

那么第三个参数就是具体的正文内容，也就是后面这段 `Hello from ESP8266`。通过这一系列语句，我们的 NodeMCU 开发板将会首先发送状态码，然后发送数据类型，那么数据类型就是为了告诉浏览器你该怎么处理这段文字，这里是纯文本信息，那么浏览器将会以纯文本的形式来显示这段文字信息。关于这个内容我们后面演示的时候大家可以看到，现在只要记住 `send` 函数它的相应操作方法是什么就可以了。

那么这个函数我讲完了，我们接着往下看后面这个函数，这个函数是 `handleNotFound`，它的作用就是来处理没有找到网页资源的时候，我们 NodeMCU 网络服务器应该发送什么信息。同样的，请看这里跟我们刚才讲解的这个 `handleRoot` 使用的是同样的 `send` 函数，只是 `send` 的内容不一样了。刚才呢是找到信息了，发的是 `200`，也就是没有问题、OK，找到信息了；但是这里虽然没找到浏览器所请求的资源，我们的这个服务器同样还是要给浏览器发送一段文字信息，这段文字信息请看这里也有所描述，它是一段纯文本信息，而这纯文本信息的具体内容就是找不到资源这一提示。关于这个程序具体的运行结果，一会儿您就会看到，我相信通过您看这个运行结果，就会对我们这个程序有一个更直观的认识。到现在这两个函数我给大家讲完了。

我们接着看，回到我们刚才这个 `setup` 函数里面，刚才我讲到 `setup` 函数结尾的地方了，那下面我们就来到这个 `loop` 函数里面了。`loop` 函数里面有一条非常重要的语句，请看这里这个函数，同样的，请看，通过 `server` 这个对象来调用一个 `handleClient` 这么一个库函数，handle 是处理，client 是客户端。在我们这段设计中，这里所指的这个客户端就是指的浏览器。那么通过 `handleClient` 处理浏览器客户端这条语句，我们 NodeMCU 开发板的每一次调用这个函数，它都会检查一下：现在是不是有浏览器向我请求这个网页信息了？如果当前有客户端请求网页信息，它就会通过刚才我们这几个函数来看一看请求信息是什么，并且把这个信息发送给浏览器客户端。

讲到这儿就必须要强调一下，如果要让我们这个服务器能够非常及时地响应客户端的请求，这个函数是必须要反复地、经常性地被调用的。因为只有在 NodeMCU 开发板执行这条语句的时候，它才会处理一下有没有客户端请求。假设 NodeMCU 开发板在处理其他工作，耽误的时间很长，那在处理其他工作的时候，它是不会理会任何浏览器的网页请求的。所以我们在这个 `loop` 函数之中把它放在这里，目的就是让它反复地被调用，只要一有浏览器请求网页信息，它就能够及时地来处理这些浏览器的请求。

## 本节要点

- 用 NodeMCU 建立的是一个「网页服务器」：浏览器通过 WiFi 局域网向开发板发送请求，开发板把网页内容返回给浏览器，整个过程可以完全发生在局域网内部，与路由器是否连接互联网无关。
- `ESP8266WebServer` 库的三个核心用法：用 `ESP8266WebServer server(80)` 建立服务器对象并指定端口；用 `server.on()` 注册「请求路径 + 请求方法」与处理函数的对应关系；用 `server.begin()` 启动服务。
- 端口号的意义：`80` 是网页服务的默认端口，浏览器访问网页时会自动使用 `80`，所以建立一个网页服务器对象时给 `80` 这个参数，浏览器才能直接通过 IP 地址访问；换个端口浏览器就无法访问网页服务。
- 请求方法：浏览器在地址栏输入地址回车时默认发出的是 `GET` 请求，点击表单提交按钮则可以发出 `POST` 请求；`server.on()` 的三个参数分别是请求路径、`HTTP_GET` 或 `HTTP_POST`、处理函数。
- `server.send()` 的三个参数：响应状态码（`200` 表示正常找到资源）、数据类型（`text/plain` 表示纯文本，`text/html` 表示网页代码），以及正文内容。
- `handleNotFound` 处理找不到页面资源的请求，返回 404 类的提示信息；`loop` 函数中的 `server.handleClient()` 必须被反复、及时地调用，服务器才能及时响应浏览器请求。
