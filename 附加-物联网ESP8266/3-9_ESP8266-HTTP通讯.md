## 正文

本节课的主题是 HTTP 协议数据通讯。之所以说这节课的内容围绕 HTTP 协议展开，请大家先回忆一下前面的学习过程：我们曾经让开发板建立一个服务器，然后用电脑上的浏览器向服务器发送指令，从而控制服务器；同时，我们也可以获取服务器上返回的信息。那是我们最初使用 ESP8266、以服务器模式来实现的一种物联网操作方式。那时候，充当客户端角色的其实是电脑上的浏览器，而我们的开发板则老老实实地待在服务器那一端，等着浏览器来访问它、给它下指令。

在之前几节课里，我给大家讲解了如何使用 ESP8266 作为一个客户端，让这个客户端通过互联网去获取网络服务器上的信息。而在接下来的课程中，我们将使用两块 ESP8266 开发板，一块作为客户端，另一块作为服务器端，用这两块开发板来实现开发板之间的数据通讯。需要注意的是，这两块开发板之间的通讯是建立在 WiFi 网络之上的。换句话说，这两块开发板连接的是同一个 WiFi，而不是通过互联网进行通讯。

讲到这里，可能有朋友会感到失望：我们讲了这么久，什么时候开发板才能真正连上互联网，向互联网发送信息、接收信息呢？请大家放心，在不久的将来，我们一定会让开发板实现通过互联网发送和接收信息。但也请不要忘记，我们现在所学的都是基础知识，要先把基础知识打扎实，后面的路才能走得更平稳。当我们了解了如何使用开发板实现彼此之间的数据通讯以后，接下来就会给大家介绍几个比较知名、比较好用的物联网平台。通过这几个物联网平台，我们就可以使用 ESP8266 开发板来实现真正意义上的物联网应用。

接下来，我们首先来看第一个开发板之间通信的应用实例。在这个应用实例中，作为客户端的那块开发板将会把它板上的按键状态发送给服务器端。这样做有什么目的呢？当我们用手指按一下客户端的按键时，服务器端的 LED 就可以被点亮，从而实现一种遥控的效果。请注意，这两块开发板现在都连接在 WiFi 上，它们之间是通过 WiFi 网络来实现遥控操作的。

我们这个示例程序有两个，为什么会是两个呢？自然是因为我们有一个是客户端，一个是服务器端。这两个程序要分别下载到两块开发板上，一块负责发送请求，一块负责接收请求，它们彼此配合才能构成一次完整的通讯过程。所以在学习的时候，请务必把它们区分清楚，不要弄混了哪一段该下载到哪一块开发板上。另外，两块开发板在上传程序之前，一定要分别确认好它们各自所连接的 WiFi 以及各自所配置的 IP 地址，这样才能保证它们之间可以顺利通信。

首先我们来看服务器端的程序。这个程序主要实现的功能，第一是接收客户端发来的请求信息，并且解析这个请求信息中的数据信息，然后把解析出来的数据信息通过串口监视器显示出来，供用户查看。这样做的好处是，我们可以一目了然地看到客户端到底发出了什么内容，服务器又收到了什么内容，双方的数据是不是对得上，这对我们调试程序、理解整个通讯流程非常有帮助。另外，这个服务器还有一个非常重要的功能：我刚才说过，按一下客户端的按键，是可以控制服务器上这个 LED 点亮和熄灭的。因此在服务器端的程序中，它还会解析客户端发出的按键状态信息，也就是客户端上面的按键有没有被按下，然后利用这个信息来控制服务器端上面 LED 的点亮和熄灭。

在 `loop` 函数里面，首先将会对我们这三个将要发送给服务器端的这三个数据进行一个操作。我们先来看第一个，`button` 它所存储的内容是开发板上按键开关的状态，是怎么获取到状态的呢？`digitalRead` 读取这个按键引脚，这没什么好说的。请看后面这两个，这两个一个是浮点型的测试数据，一个整数型的测试数据，我们就让它实现一个自加，让它们产生一个变化。通过这个变化，我们就可以看到服务器端所收到数据和客户端所发送的数据是不是相吻合。这些就是一些测试性的数据，没有什么实际意义。

我们继续往下看，我们来到这里，这里将会调用一个叫做 `wifiClientRequest` 的这么一个函数，这个函数就在 `loop` 函数的后面。通过这个 `wifiClientRequest` 函数，我们的开发板就会实际地向服务器发送请求信息，这些信息里面就是我们这几个数据的内容了。把发送请求这件事单独封装成一个函数，是我们编程中经常采用的一种做法，好处是 `loop` 函数里只剩下简简单单的一两行，程序的主干一眼就能看清，而具体的通讯细节都收在函数里面，需要修改的时候也只需要动一个地方。以后大家自己写稍大一点的程序时，也可以有意识地这样去组织代码。

当然了，在目前我们这个项目中，服务器端和客户端都是我们自己的，这个问题不大。不过在我们未来开发过程中，可能我们这个客户端将会向互联网上的某一个服务器发送请求了。在这样的开发环境中，我们就必须要注意，要珍惜资源了。可能讲到这里，有的朋友有点糊涂了：怎么突然蹦出一个珍惜资源的话题，我们要改成环保演讲了？当然了，环境资源、社会资源这些资源都非常珍贵，我们也要珍惜。不过我在这里主要强调的是，我们要珍惜的是互联网或者说是物联网资源。

怎么叫珍惜物联网资源呢？就是说我们的物联网设备在执行每一个操作的时候，我们都要想一想它所执行的这个操作是不是有意义。比如说未来我们要开发一个智能家居的这么一个项目，这个智能家居项目中有一个 ESP8266 这个开发板，它要定时从一个互联网上的一个服务器获取天气预报的信息，这个天气预报信息在这个互联网服务器上是每隔一个小时更新一次的。那现在我们这个 ESP8266 开发板，甚至我们可能每隔 0.1 秒钟就让它向服务器发一个请求来获取这个天气预报信息，这是没有什么用处的。因为那个天气预报信息在服务器端它一个小时才更新一次，你过于频繁地来请求，这种操作是一种很糟糕的操作，它将大量地浪费网络资源以及服务器资源，严重的话会把我们的客户端当做一个黑客攻击设备。如果出现这种情况，那很有可能管理员会把我们的 IP 封了，或者把我们这个设备所访问的权限封掉，那这个就不是我们想要看到的结果。

因此我们在使用物联网设备来执行任何一个操作的时候，都要想清楚我们这个操作有没有意义。毕竟我们这个设备是一个物联网设备，它是存在一个网络中的，它的一举一动都有可能会影响到其他设备。所以我们要遵守物联网开发的一些规则，以及尊重物联网家族中的每一个成员。对其他人的尊重就是对我们自己的尊重，对规则的遵守就是对我们自己的保护。好，我在这里说得有点多了。目前我们还是刚刚进入到物联网开发这个世界里面来，所以现在我想先给大家灌输一个非常基本的概念，这样在后面的开发中尽量让我们少走弯路。

接下来我们来看一看这个 `wifiClientRequest` 这个函数中的内容。首先第一句，建立一个 `WiFiClient` 对象，这个对象名称叫 `client`，我们将用它来实现客户端向服务器发送请求这个操作。接下来请看这里，这里建立一个字符串型的变量。这个字符串型的变量所做的事是什么呢？请您看是不是有点眼熟呢？这个变量所存储的内容正是我们客户端向服务器发送请求的地址信息中，请看这个 IP 地址后面的这一部分内容：斜杠 `update` 问号 `float=` 多少 `&int=` 多少 `&button=` 多少。

我们回到我们刚才这个变量中去，在这里，为了便于观察，我们把 IP 地址后边这个信息放在这里。请看斜杠 `update` 问号，紧跟着 `float=`，然后请看这里，就是这个 `float` 这个参数的具体数值信息了。在我们这里，请看是通过这一串来表达当前这个 `float` 这个参数的数据是多少，是怎么来实现的呢？自然是先要使用我们这个变量的这个信息，这个变量它是在 `loop` 函数中的，你看这个变量是在 `loop` 函数中不断进行自加操作的，我们要它在不断地改变数值，从而确定我们服务器收到的和客户端发出的是相匹配的。

那么这个变量我们是对它进行了一个数据类型转换的操作，我们把它从一个浮点型的数值转换成一个字符串型的数据，然后我们再把这个字符串和之前的这一部分内容把它们连接在一起。这里这个加号就可以把字符串连接在一起，后面我们还有很多加号，都是来起到连接这一个一个字符串部分的作用，最后把它形成一整个字符串，也就是形成这个样子。我们继续往下看，继续把这个字符串连接，连接什么呢？`&int=`，等于这个整数型的测试数据的数值了，我们同样把它进行一个数值类型的转换。使用这个，然后是 `&button=`，最后呢这个是服务器端的开发板 server 首字母 s，那么这是服务器端，自然这就是客户端了。

我们通过客户端上的这个按键是可以控制服务器端的 LED 点亮和熄灭的。我们看一下，首先按一下，没问题，服务器的 LED 被点亮了；离开，熄灭了；按下点亮，熄灭。我们是通过客户端发送请求信息到服务器端，这个请求信息中按键状态信息长什么样子呢？我们可以在屏幕上请看，我鼠标所指这个地方，这地方有实时输出很多信息，这里面就输出了我们客户端所发出的这个请求信息的内容了。其中在这个发送请求信息中我们可以看到，请看这里有三个数值：第一个 `float`，这是发出这个浮点型的数值，请看这是浮点型数值的测试数值；后面这个 `int`，这是整数型测试数值的这个数值 192；那最后一个这个 `button`，这个就是客户端上面这个按键的状态信息了。

我们现在恢复成自动滚屏。接下来我们来按一下这个客户端的这个按键，我们会看到最后这个 `button` 的数值：按下变成低电平了，变成 0 了；离开，又恢复成 1 了。那么这个信息会被服务器端所接收。服务器接收到以后，请看我们在屏幕上还有一个串口监视器，这个串口监视器里面所输出的信息就是它所接收到的客户端的信息内容了，在实时地变化。你可以看到，我们客户端所发出的信息和服务器所接收的信息是相匹配的，请你仔细观察一下，这个数值是在实时更新的。比较明显的是可以看到我们最后这个按键开关的信息，请注意，我按下这个客户端的按键，马上我们服务器端这个按键开关的信息就变成 0 了；我离开，变成 1；按下变成 0。可以很明确地知道，现在服务器端已经完整地收到了客户端所发出的这些数据信息了。

在做这个实验的时候，请大家注意两个串口监视器要分别打开。因为我们有两块开发板，它们各自连接在电脑的不同串口上，所以我们要同时打开两个串口监视器窗口，一边观察客户端发出去的内容，一边观察服务器端收进来的内容。只有两边对照着看，我们才能真正体会到数据是从一边流到另一边的，这对于理解客户端与服务器之间的请求与响应关系非常有帮助。

在这个演示的过程中，我们可以清楚地看到：客户端的按键状态一变，服务器端的 LED 就在同一时刻跟着变化，两边几乎是没有延迟的。这说明我们的请求是畅通的、数据是准确的。如果大家在实验中发现服务器端迟迟没有反应，那首先要检查的就是两块开发板是不是连在同一个 WiFi 上，其次是检查客户端程序里写的那一行服务器 IP 地址，是不是和服务器端实际配置的 IP 地址完全一致。

好了，通过刚才的演示，相信您已经看到我们这两个示例程序在控制我们这两个开发板的工作状态了。那么讲到这里，最后有一个小知识点我需要给大家补充一下。这个是我们现在客户端这一段的这个程序内容，在这个程序中，我们刚才说建立这个 HTTP 请求信息的时候，我们使用这个请求方法应该是 `GET` 这个方法。可能有朋友在看到这个方法以后会感到好奇：我们在之前给大家讲课的时候曾经跟大家说过，当我们的客户端想要从服务器获取信息的时候，我们使用 `GET`；而在我们这个示例中，我们的客户端并没有向服务器获取信息，而是向服务器发送信息，怎么发送信息、获取信息都用 `GET` 呢？实际上在这个 HTTP 协议中，它没有非常严格的规定说哪一种操作必须用哪一种方法，用 `GET` 既可以从服务器那里获取信息，也可以向服务器发送信息。

到这里我们就完成了第一个开发板间通讯的实例讲解。在这个实例中，我们的客户端将不断地把开发板上的按键状态发送给服务器端，那么服务器端接收到以后，就会通过客户端这个按键来控制它上面这个 LED 的点亮和熄灭。整个过程中，数据是从客户端流向服务器端的，这也正是我们刚才所说的「向服务器发送数据」这个名称的由来。

那接下来我们来学下一个实例。这个操作其实是反过来的操作，也就是通过这个服务器端的按键开关，我们来控制客户端的这个 LED 点亮和熄灭。在这个实例中，我们的客户端将会不断地向服务器发送请求信息，那么服务器端在接收到客户端的请求信息以后，将会把它这个开发板上按键状态响应给客户端。当客户端接收到了服务器端的响应信息后，就可以利用响应信息中的按键开关状态来控制板上的 LED 点亮和熄灭了。也就是说，这个实例中数据的方向变了：客户端虽然仍然是发起请求的一方，但真正有用的数据是从服务器端返回给客户端的。

接下来我们看看这个操作的详细内容。接下来我给大家讲解的程序是在「客户端向服务器请求数据信息」这个链接页面中，这个链接是在刚刚给大家讲解这个「客户端向服务器发送数据」的内容的下面，在这里是 3-4-3-2 这个链接，我们点击它。在这个新打开的页面中，同样还是有两个示例程序，一个是服务器端的，一个是客户端的。我们还是先看看这个服务器端程序，我们把这段示例程序复制粘贴到 Arduino IDE 中。

接下来我们就来看看这段示例程序的主要内容。我们这边示例程序是服务器端的内容，它所实现的功能首先是实时获取服务器端按键的引脚状态，并且当有客户端向服务器发送请求的时候，把这个引脚状态通过响应信息发给客户端，主要实现这个功能。接下来我们来看怎么实现的。因为这个程序中没有什么新的知识，所以我在这里会讲得比较快。

首先我们来看程序刚开始有 3 个 `#include`，这 3 个库太熟悉了，不多说了。接下来一个宏定义，这是便于我们的按键操作的，因为我们的开发板上的按键是连在引脚 3 上的，这也没什么好说的。下面建立 `ESP8266WiFiMulti` 对象，这个联网用的；接下来建立服务器对象，监听端口 80；还是用来控制服务器的。接下来这些对象是用来设置 ESP8266 开发板的 IP 地址的，这些我刚给大家讲过。

我们继续往下看，这里建立了一个布尔型变量，它是用来存储按键引脚状态用的。下面我们就进入到整个程序的 `setup` 函数部分了。启动串口通讯，设置按键引脚的模式为输入上拉模式。继续，这里我刚刚给大家讲过，使用 `config` 函数来设置开发板的 IP 地址。我们继续往下看，以便于联网使用。这里开始尝试联网，连接成功以后通过这里来输出联网的这些信息，这些我们都已经见过太多次了，不浪费时间了。

我们再往下看，这里，这里和上一个示例程序的操作是完全相同的。当客户端请求我们这个服务器的 `/update` 的时候，我们让它执行这个 `handleUpdate` 函数。请看这就是 `handleUpdate` 这个函数的全部内容了。这个函数虽然很短，但它是整个服务器端程序的核心，客户端的每一次请求最终都是落到这个函数里来处理的。所以我们在阅读这类程序的时候，可以先抓住路由注册的那几行，找到请求地址和函数名之间的对应关系，然后再跳到函数定义的地方去细看它到底做了什么事。掌握了这个思路，以后再看到更复杂的服务器程序，我们也能很快理清它的结构。在这里请看，首先我们来获取服务器端开发板上按键的引脚状态，通过 `digitalRead` 来获取。接下来这个逻辑判断语句，如果读取到的引脚状态是低电平的话，请看我们让这个 `buttonState` 这个变量存储数值 0；如果是高电平，就存储数值 1；如果不是低电平存储数值 0。

接下来将会用这个 `buttonState` 这个变量，我们就要把它发给客户端了。怎么发的呢？请看通过这个 `send` 这个函数，先发一个响应状态码 200，告诉它没问题，你要的信息我马上给你发送过来了。然后发什么信息呢？就在这里，这是发的实际的响应信息的内容。这响应的信息内容有两部分，前半部分是一个 `buttonState:` 冒号加空格，后边呢这是一个加号组合一下，组合什么内容呢？就是具体按键引脚的这个状态信息，到底是一还是零，把它组合起来。完成这个组合的操作以后，接下来服务器就可以通过 `send` 函数将信息发回给客户端了。

那么客户端收到这个信息以后，就可以通过解析这个信息的内容来获取到服务器上这个按键状态，并且利用这个状态信息控制它板上 LED 点亮和熄灭。具体怎么操作的呢？那下面我们来看看客户端程序的具体内容。这个客户端程序在刚刚给大家讲解的这个服务器端程序的下面，请看这里，这是服务器端的程序内容，我刚给大家讲解完，在它下面就是我们马上要讲解的一个客户端程序了。

这个程序将控制客户端开发板定时地向服务器发送请求，从而获取服务器开发板上按钮的状态，并且将服务器发的这个按钮状态解析为一个数字量，再利用这个数字量来控制客户端开发板上的 LED 的点亮和熄灭。下面我们把这个客户端的程序复制并粘贴到 Arduino IDE 中去，我们看看具体内容。这段示例程序同样没有什么新的知识，请看，刚一开始两个 `#include`，这两个库不用我多说了，真的太多次了。建立 `ESP8266WiFiMulti` 对象，用来联网用的。然后建立两个常量，第一个常量是用来存储服务器的 IP 地址的，第二个是服务器连接的端口号 80，没有什么说的。

然后设置引脚状态，把 LED 引脚设为输出模式，并且在让它开机的时候我们把这个 LED 关闭。连上以后输出信息，`setup` 函数就结束了。进入到 `loop` 函数，我们看 `loop` 函数里面两条语句。这个呢是调用 `wifiClientRequest` 这个函数，这个函数的作用就是向服务器发送请求信息，并且获取到这个服务器响应信息，解析出响应信息中的按键状态，然后控制 LED 的点亮和熄灭。这个函数非常关键。在这个函数后面有个 `delay`，这个 `delay` 就是让我们调用这个函数的频率不要太快，否则的话不便于我们待会演示的时候观察这个程序的运行状态。那么 `loop` 函数讲完了，我们接下来就要看看这个 `wifiClientRequest` 这个函数了。

下面我们看一看这个 `wifiClientRequest` 这个函数。这个函数在这里，函数刚一开始，建立 `WiFiClient` 这个客户端对象。接下来建立一个布尔型的变量，它是用来存储服务器端按钮状态的。接下来通过串口监视器告诉我们，马上开发板也要开始尝试连接了，连接谁呢？连接服务器了。连接服务器的这个具体操作是怎么来实现的呢？请看通过这个逻辑判断语句中的这条语句 `connect` 函数，连接这个服务器的这个端口，这些都是在我们程序刚开始设置的。

如果一旦连接成功，那么将一个字符串型的变量叫 `httpRequest`，它里面所存储的内容就是向服务器所发出的这个请求信息。其中最关键的一点是，请看请求的这个地址是斜杠 `update`，通过这个请求，服务器就会把开发板上的按键状态响应回来了，必须得是将这个地址发送请求才能让服务器响应。这个请求信息建立完成以后，接下来请看客户端将会通过这条语句 `client.print`，这一句把请求信息发到服务器上去。

发送完服务器请求信息以后，接下来我们就要等着服务器的响应信息了。如果服务器发回来响应信息的话，我们将在服务器的响应信息中，请注意这里，这里我们执行了一系列的 `stream` 数据操作。什么是 `stream` 数据呢？就是服务器的响应信息。这个响应信息我们知道它是一个 stream 数据，我们要针对这个响应信息来查找它这个数据中有没有 `buttonState:` 这一串字符。这串字符的的确确是在响应信息中是存在的，为什么这么说呢？刚才给大家讲解这个服务器中这个 `handleUpdate` 这个函数中，请看我们在发送给客户端的这个响应信息中就是有这么一段 `buttonState:`，冒号再就是字符，后面请看就是开发板按键的开关状态了。这里所说的 stream 数据，大家可以把它理解为一种按顺序读取的字符流，我们只能从头往后一个字符一个字符地去找、去读，所以我们才要先用查找的方式定位到关键字的开头，然后再接着往后取需要的内容。

那我们还回到客户端这个程序中来，我们让开发板找到这个 `buttonState:` 这串字符以后，紧跟着我们来继续让它执行一个新的 stream 数据操作，是什么操作呢？请看通过这条语句，让客户端在接收到的响应信息中找到了 `buttonState:` 以后，在这个信息的后面找有没有整数信息。整数信息肯定是有的了，我们在建立这个响应信息的时候，我们就是把开关状态放在 `buttonState:` 后面了。所以请看，我还回到这个客户端程序中了，那么所以我们在客户端程序中，当我们找到了 `buttonState:` 冒号以后，后面肯定是能找到一个整数的。找到整数以后把这个整数的数值赋值给 `buttonState`，然后我们要开发板通过串口监视器把 `buttonState` 这个值说出来，以便我们观察。

服务器端上的它这个 LED 也被点亮了，正是利用这个服务器端的按键开关状态来实现客户端这个 LED 的点亮和熄灭。接下来我将会把手指从这个按键上移开，请注意。我移开了，我们先来看一看这个客户端这个 LED，我们看到 LED 被熄灭了。另外我们也可以看到在这个串口监视器中的它所获取到的服务器端的引脚状态，从刚才的 0 又变成 1 了。

这个程序就像你演示的，我们是如何使用客户端来向服务器请求信息内容。目前我们只请求一个数据，这一个数据我们大家可以看到，就是在每次客户端向服务器发送完请求以后，请看，发送完请求以后，现在客户端要等一会儿，再等一会儿。原因是什么呢？等一会儿是因为这个客户端它要从服务器的这个响应信息中解析出这个按键的这个数值，这个解析过程其实是挺慢的。你想现在我们只有一个数值，让我们的这个客户端开发板来解析；原来假如说我们这个服务器上面有十个或者上百个这样的数值，如果要是这么多数据让我们的客户端来解析的话，这个等待时间呢是挺恐怖的。有没有什么更好的办法来解决这个问题呢？请继续看我后面的讲解。

在刚才的实验中，我们看到了通过客户端解析服务器的响应信息这个操作。虽然可以得到我们想要的数值，但这个工作效率不是特别理想。假如我们这个数值比较少，用 stream 数据解析这种方法还可以实现；假如数据要多了的话，单单依靠数据解析这个效率太低了。这个就要引出我们接下来给大家讲的下一个话题了，是什么呢？就是这个 JSON。JSON 是在网络通讯中非常非常常用的一种数据格式，通过 JSON 那关于 JSON 的知识呢，我们下节课给大家介绍。

我们不妨先给大家透露一点点。JSON 的好处在于，它可以把很多个数据按照一定的结构组织在一起，每个数据都带着自己的名字，服务器发过来的一整段内容，客户端可以一次性地读懂，不需要再像现在这样，用查找字符、再往后取整数的办法一个一个去猜、去抠。数据越多，这种优势就越明显。所以从下一节课开始，我们就要认真地来学习 JSON 这种数据格式了。这节课的内容到这里就结束了，非常非常感谢您，我们下节课再见。

## 本节要点

- 本节课围绕 HTTP 协议数据通讯展开，使用两块 ESP8266 开发板（一块作客户端、一块作服务器端），在同一个 WiFi 局域网内实现开发板之间的数据通讯。
- 通过 `IPAddress` 对象可以固定开发板的 IP 地址、网关、子网掩码，必要时还可配置 DNS；前三段必须与网关保持一致才能处于同一子网，且不能与网络中已有设备的 IP 冲突。
- 可用 `ipconfig` 命令查看本机网络的默认网关地址，作为配置开发板网络参数的依据。
- `WiFi.config()` 用于设置网络参数，返回值为假时表示配置失败；程序中对返回值取非，用于在配置失败时通过串口输出提示。
- 服务器端程序用 `ESP8266WebServer` 对象监听 80 端口，通过注册路由（如 `/update`）触发 `handleUpdate` 函数。
- 客户端把数据通过 URL 查询字符串发送，参数用 `&` 分隔，例如 `/update?float=1.5&int=2&button=0`。
- 服务器端用 `server.arg()` 获取参数值，得到的都是字符串，需要用 `toInt()`、`toFloat()` 等函数转换成对应的数值类型。
- 服务器通过 `send()` 先返回状态码 200，再返回响应内容（如 `received` 或 `buttonState:1`），客户端则用 stream 数据操作在响应文本中查找关键字并取出后面的整数。
- 在 HTTP 协议中并没有严格规定哪种操作必须用哪种请求方法，`GET` 既可以从服务器获取信息，也可以向服务器发送信息。
- 物联网设备应谨慎控制请求频率，避免无意义的频繁请求浪费网络与服务器资源；频繁请求可能被管理员封禁 IP 或访问权限。
