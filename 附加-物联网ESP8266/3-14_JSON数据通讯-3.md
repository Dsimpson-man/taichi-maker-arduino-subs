## 本节要点

- 本节把 JSON 数据通讯由「客户端请求」推进到「客户端主动发送」，客户端定时向服务器发送含引脚读数的 JSON 信息。
- 发送用的 JSON 结构与上一课完全一致，分 `info`（三个字符串）、`digital pin`（三个引脚读数）、`analog pin`（模拟引脚读数）三部分。
- 完整 HTTP 请求由三部分构成：请求行、请求头、请求体，请求行与请求头之间用 `\r\n` 分隔，请求头结束的标志是出现空行（两个连续 `\r\n`）。
- 要发送的 JSON 信息必须放在请求体中，即请求头结束的空行之后，这一点是后续服务器解析 JSON 的关键。
- `WiFiServer` 与 `ESP8266WebServer` 功能相似，但要获取客户端请求信息中的详细内容时，必须使用 `WiFiServer` 库。
- `WiFiServer` 对象用 `begin()` 启动并持续监听端口 80；`runServer()` 中仍要建立 `WiFiClient` 对象（`incomingClient`）来处理客户端请求，两个库密不可分。
- `incomingClient` 可以作为逻辑判断条件：没有客户端请求时它是空值（逻辑零），取非即为真，程序直接 `return`，由 `loop()` 反复重试。
- 服务器端跳过请求头的方法是调用 `find()` 查找第一个空行，剩下的部分就是请求体中的 JSON，再交由 `parseInfo()` 解析。
- `parseInfo()` 中先用 `capacity` 计算 JSON 大小，再建立 `doc` 对象，通过 `deserializeJson()` 把 `WiFiClient` 对象解析进来。
- 解析结果分三部分依次处理：`info` 的 `name`、`digital pin` 的引脚 3 读数、`analog pin` 的 `A0` 读数；最后用引脚 3 的数值控制服务器端 LED 的亮灭。
- 课后作业：参考「示例 2」，改用 ArduinoJson 库来建立 JSON 信息，并把 JSON 分成几部分分别发送给服务器。
