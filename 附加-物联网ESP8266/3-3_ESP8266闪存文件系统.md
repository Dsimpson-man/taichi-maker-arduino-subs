大家好。这节课我们来学习 ESP8266 的闪存文件系统。这个闪存文件系统的主要作用，就是给 ESP8266 存储文件使用。那么它具体存储什么文件呢？比如说我们通过 Arduino IDE 所编写的控制程序，正是通过 IDE 上传并且存储在闪存文件系统中的。另外，除了我们自己写的这些控制程序以外，ESP8266 它的配置文件以及它的一些系统文件也存储在这个闪存文件系统里。

这个闪存文件系统还能帮我们解决一个问题，什么问题呢？请大家回忆一下，在上节课里我给大家讲述了如何使用 ESP8266 开发板来实现一个网站服务器，那么当时我们这个网站服务器所有的页面代码都是写到程序里面的。这么做一方面是比较容易，但是它有个缺点：假如我们这个网页比较复杂，或者说我们这个网页不光是有纯文字的内容，可能还会有图片或者视频这些内容，那么光使用程序来存储我们这个网页代码的话是不太现实的。所以我们要更好地利用 ESP8266 它的闪存文件系统，让 ESP8266 开发板存储更多的文件，这样我们所开发的物联网项目的功能也会更加丰富一些。

接下来我给你们介绍一下 ESP8266 开发板它的闪存文件系统的一些基本知识。通常来说，ESP8266 开发板它的闪存文件系统大小是 4MB，注意我说的是通常来说，并不是所有的开发板都是 4MB 的闪存文件系统，可能有的大一些，有的小一些，具体有多大，这个需要您跟购买这个开发板它的这个商家了解一下确认。另外，我在接下来的课程中还要给你介绍一个方法来确定您手中的开发板它的闪存文件系统到底有多大。

在这个闪存文件系统中，有 1MB 的空间是留给我们来上传我们所写的控制程序的。注意我在这儿说这 1MB，指的是我们这个程序在编译以后的大小，而不是源文件的大小。我们的程序文件存储在电脑上，我们是可以通过电脑来查一下这个程序文件多大，那个文件大小只是源文件大小，而并不是编译后的大小。编译以后这个程序大小，是通过我们 IDE 编译程序以后在 IDE 下方能显示出来这个信息。讲到这儿，如果朋友不太确定我如何能够看到我这个程序编译以后的大小多少，没关系，我一会儿再讲程序的时候会给你指出来。

那么除了可以用于存储程序的这 1MB 空间以外，剩余的这 3MB 空间就是 ESP8266 开发板用来存储文件使用的这个空间了。那么请您注意，我们这剩下的 3MB 并不是完全都可以使用，其中有一部分是 ESP8266 用来存储系统文件的，所以我们实际可以使用的这个文件存储空间大概是小于 3MB 的。具体多大，要根据 ESP8266 开发板它在不同应用场景会有一些变化，在有些应用场景中它可能能用的空间稍微大一点，有些则会小一点。不过从我的经验来判断，假如我们想要上传的文件总和在 2.5MB 左右的时候，这是问题不大的，小一点五兆自然也没问题，那超过 2.5MB 或者是更大的时候，有时候就会有一点问题。好，那么以上呢就是我们这个闪存文件系统它的一些基本概念。

另外，大家也已经看到了，我们把这条语句放到了一个逻辑判断语句中作为一个逻辑判断条件，它的原因就是这个启动闪存文件系统的这个 `begin` 这个函数，它的返回值可能是真也可能是假。如果我们的 ESP8266 开发板成功地启动了闪存文件系统的话，它将会返回一个真值，如果返回真值的话，请看，我们就让这个系统通过串口监视器告诉我们启动成功；反过来，如果这个 `begin`，也就是启动闪存文件系统失败了，那就通过这个串口监视器告诉我们启动失败了。那么这一系列语句的作用，就是通过这条语句启动，并且告诉我们这个启动的结果。

## 本节要点

- 闪存文件系统的作用：存放 ESP8266 的配置与系统文件，也存放我们用 Arduino IDE 上传的控制程序；其中约 1MB 用于存放程序，剩余约 3MB 用于存放文件，实际可用空间会略小于 3MB。
- NodeMCU 的闪存通常为 4MB，具体容量可在程序编译上传后从 IDE 提示信息中的 `Auto-detected Flash size` 看到。
- 使用闪存文件系统必须先在「工具」菜单的 Flash Size 中选择 `FS: 1MB` 或更大的选项才能正常工作；如果选成 `None`，`SPIFFS.begin()` 会启动失败。
- `SPIFFS.format()` 用于格式化闪存文件系统，可把里面所有内容清除干净，常用于拿到旧开发板时清空环境；`SPIFFS.begin()` 用于启动文件系统，返回真值表示启动成功。
- `SPIFFS.open(路径, 模式)` 是核心函数，模式字符决定了操作类型：`"w"` 表示写入、`"r"` 表示读取、`"a"` 表示在文件末尾追加内容。
- 写入与追加的区别很重要：文件不存在时两者的效果相同；文件已存在时，`w` 每次执行都会覆盖原有内容，而 `a` 每次执行都会在文件末尾追加一行，执行几次就追加几行。
- 读取文件用 `file.read()`，它每次只能读出一个字符，所以要配合 `for` 循环和 `file.size()` 反复读取；输出时必须用 `(char)` 转换，否则串口打印出来的是字符的 ASCII 码而不是字符本身。
- `SPIFFS.exists()` 用来判断某个文件是否存在，`SPIFFS.remove()` 用来删除文件，两者都返回布尔值，可以放在 `if` 语句中直接判断操作结果。
- 操作文件夹用目录对象：`Dir dir = SPIFFS.openDir(路径)` 打开目录，然后配合 `while` 循环反复调用 `dir.next()`，每调用一次指针就指向下一个文件并返回真，直到返回假表示已经没有文件了，此时用 `dir.fileName()` 可以取得当前文件的名称。
- 用 `File` 建立的文件对象在操作完成后必须调用 `close()` 关闭，避免程序运行时对文件造成误操作。
- 常见排查思路：通过列出目录内容，可以确认文件是否真的上传成功、文件名有没有写错，这是后续做网页文件、图片文件项目时非常实用的手段。
