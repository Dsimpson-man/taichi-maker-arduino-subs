在前面两节课里，我们已经掌握了如何使用 ESP8266 客户端向 ESP8266 服务器请求 JSON 信息，也就是服务器端响应给客户端 JSON 信息的这套操作。但是这套操作存在一个比较明显的缺陷，那就是服务器响应给客户端的信息只有一种，它只会一股脑地把所有要发给客户端的信息全部响应出去。在这种情况下，客户端实际需要的数据可能并没有这么多，它也许只想要服务器端的某一个或者某几个数据。如果每次都让服务器把全部数据都响应给客户端，那么对我们的网络资源是一种相当大的浪费。

## 本节要点

- 服务器原来只会把全部 JSON 信息一次性响应给客户端，对网络资源是很大的浪费，需要优化为按需响应。
- 优化思路：把 JSON 信息拆成 `info` 与 `digital pin` 两部分，服务器针对不同请求地址只返回对应部分。
- 在 `setup()` 中新增两条路由注册语句，为客户端增加 `info` 和 `digital pin` 两个新的可访问地址。
- 新增 `handleInfo()` 与 `handleDigitalPin()` 两个处理函数，分别用 `send` 发送状态码 `200` 并返回对应 JSON 字符串。
- 新增 `infoJson()` 与 `digitalPinJson()` 两个生成函数，结构照搬 `rootJson()`，用 ArduinoJson 在线工具生成代码后加工。
- 对在线工具生成的代码要调整 `capacity`（本例分别加了 90 和 30），并把结果从 `Serial` 改为写入字符串变量，通过 `serializeJson()` 生成。
- 客户端方面：给 `httpRequest()` 增加 URL 参数，使一次循环中可以请求多个不同资源（首页、`info`、`digital pin`）。
- 客户端解析时要用 `if` / `else` 判断响应中是否含有 `info`、`digital pin`、`analog pin A0` 等对象或数值，再决定是否解析。
- 解析出的 `info name` 等常量指针需转换为字符串类型才能使用；`digital pin` 中的引脚 3 数值可直接通过串口监视器输出。
- 串口监视器实测结果：请求首页时三部分都有；请求 `/info` 时只有 `info` 为 true；第三次请求时只有 `digital pin` 为 true，验证了按需响应确实生效。
