## 正文

不知道大家有没有印象了，咱们整个零基础入门学用 Arduino 教程最开始的基础知识篇里面，我们曾经给大家讲过，这个 Arduino 开发板它最核心的元件就是开发板上的这一款 ATmega328 微控制器。那么作为整个开发板的核心元件，这个 ATmega328 微控制器一方面是执行我们上传给 Arduino 的这些程序，并且让 Arduino 开发板根据我们的程序内容进行工作；另外一方面呢，这个微控制器的内部还设置有存储单元。那么我们之前的课程里面一直是着重关注如何来编写 Arduino 程序、让开发板按照我们的意图来工作，那么这节课我们就一起来好好学习学习这个微控制器它的存储单元的结构和基本工作原理。掌握这些知识的目的，一方面是让我们以后编写的 Arduino 程序可以在开发板上运行得更加高效、更加稳定，另外一方面也是可以让 Arduino 实现我们以前不知道如何实现的一些新的功能。好吧，我（是）废话少说，让我们开始吧。

微控制器呢，它的内部存储单元是由几种不同的存储介质所组成的。第一种叫做 Flash，这个 Flash 就是常常我们说的这个闪存，换句话说，我们每天使用的这个 U 盘就是这种存储介质。除了 Flash 闪存以外，微控制器内置的存储单元还有一种介质，它的名字叫做 Static RAM，中文名字叫做静态随机存储器。说到这儿，可能有朋友会问了，既然都已经有了闪存，干嘛没事还得要搞一个什么"静态"还"随机"还"存储器"呢？搞这么复杂干什么呢？其实是有原因的，请看哈。因为我们的闪存 Flash 它的特点是价格比较低廉，但是它的读写速度相对的要慢；同时呢，静态随机存储器它正好和闪存形成了互补，也就是说它的特点是价格比较高，但是它的读写速度要比闪存快得多得多得多。假如我们的微控制器只有闪存作为存储介质，没有静态随机存储器，那么它的运行速度将会慢得让人难以接受了，同时它有很多功能也没办法实现，尤其是那些对时间、对运行速度要求比较高的功能，这些功能如果只有闪存是不可能实现的。所以呢，微控制器里面才会多了这一块静态随机存储器 Static RAM。

那么也正是因为这两种存储介质它各自的特点，我们用它们来存储的内容也是各不相同的，请看哈。当我们用 Flash 闪存的时候，我们主要用它来存储一些数量较大的静态信息；那么对于静态随机存储器来说，我们常常用它来存储一些数量较小的动态信息。说到这儿，我们就得好好地解释一下什么是静态信息、什么是动态信息了。所谓静态信息，就是在 Arduino 运行过程中这个信息不发生任何改变，那这种信息叫做静态信息；那么动态信息相反，就是在程序运行中这个信息是经常变化的。具体举个例子来说，所谓静态信息，就是请看，Arduino 程序就是一种静态信息。因为当我们把程序写好并且编译上传给 Arduino 以后，Arduino 只会认真地一条一条地执行我们的程序，它是绝对不会把我们的程序做任何的修改的，那么对 Arduino 来说，我们给它的这个程序就是一个静态信息，是不发生任何改变的。那么与其相对应的动态信息我也给大家举个例子，请看，在程序运行过程中，这个程序变量是经常发生变化的，那么程序变量就是一种动态信息，它呢就是由 Static RAM、由静态随机存储器来储存和处理的。

讲到这，我突然发现一个挺有意思的事儿，请看哈：Flash 闪存，"闪"感觉应该挺动感的一个名字哈，但是它又恰恰是用来存储静态信息的；那么相对应的，Static RAM 静态随机存储器，感觉是一个挺文静的一个小家伙，但它又正好是用来存储动态信息的。其实呢，这对小冤家他们的名字和他们所处理的信息内容（是）毫无关联的，而他们的名字是来自于他们的工艺、他们的技术，感兴趣的话，我建议您可以在网上查一查他们这两个名字的来历，还是挺有意思的。

说了这么多这两种存储介质的特点以后，还有一点也是我必须要给您提的，就是 Flash 和 Static RAM 它们在断电以后能够保持存储内容的状态是不一样的。对于 Flash 来说，当我们把电断了以后，那么 Flash 里面所存储的内容是可以保持住的；那相对应的，Static RAM 在断电以后它里面所存储的内容就被丢失了。这点也很好理解，你可以想一下，当我们把 Arduino 开发板的电源关闭以后，这时候我们在 Arduino 开发板里边所存储的程序不会因为没有电而丢失；但反过来，当 Arduino 开发板运行一段时间以后，我忽然把它电源关闭了，那么这个时候所有程序里面的变量内容也就会随之被清空了，那么等下一次再给它通电以后，这些程序里面的变量内容将会再次随着程序的运行发展进行相应的调整、相应的变化。

那么讲到这儿，我不知道您是不是和我也曾经遇到过相同的问题，就是有时候我们在开发一些小项目的时候，那我们在这个项目里面有一些变量，它的数值是要 Arduino 能够记住的，也就是说在它能够断电以后，它能够把这些变量的数值留存住，而不会因为断电了这些数值就被清空了。比如说请看下面这个例子，您现在在屏幕上看到的就是我们这一系列教程后面将引领您一起制作的一款智能灯。这款智能灯既然叫智能灯，自然而然我们用户是可以来调节它的颜色的。比如说我喜欢蓝色，那么我就要把它刚刚的这种比较暖白色的光调成蓝色。但是呢，我不可能让我们这款智能灯永远地保持通电的状态，有时候我把它电源关闭了，那么下次我再开机的时候，这个时候这款智能灯又恢复到初始的这个灯的颜色了，我还想要把它调成我喜欢的颜色，我就要再重新设置。老实说，这么做太麻烦了。那么有没有什么办法，能够让控制这个智能灯颜色和亮度的 Arduino 在每一次开机的时候都能够记住这个智能灯的亮度和颜色？换句话说，让它在每次启动的时候都能够用相应的变量把这个灯调节到我喜欢的颜色和亮度上面去。那么这个就需要用到微控制器它内部存储单元里面的一种新的存储介质了，它的名字叫做电可擦除可编程只读存储器，也叫 EEPROM。这个 EEPROM 这个名字又长又怪，其实呢，这个名字和它的进化过程是有一定关系的，那下面我给您简单地介绍一下这个 EEPROM 它是如何进化的。

首先我们来看这串名词的第一个关键词"存储器"，这个不用浪费时间了吧，存储器就是存储信息的地方。好，接下来我们来看"只读存储器"，顾名思义了，它只能用来读取信息，而不能写入信息，这种存储器就叫做只读存储器。比如说我们看到左边这个 CD 或者 DVD，那么右边这个，不知道你还认不认识它，反正我认识，一不留神暴露年龄了，那个东西如果您认识也就认识，不认识就算了，它们都是只读存储器的很好的例子。接下来我们来看"可编程只读存储器"，这种存储器的特点是，我们可以通过向它施加电流的方式来把程序固化到它的存储器中去，但是这种存储器的特点是只能写一次。可能有朋友问，假如程序写错了怎么办呢？不好意思，程序写错了，这个存储器也就只能报废了。由于可编程只读存储器只能写一次，不是很实用，于是便演化出了"可擦写可编程只读存储器"，这种存储器它的特点是可以把存储在里面的内容擦写掉，那么具体操作方法呢？请看，在它的芯片的上面有一个小窗户，我们只要用紫外线来照射它，就可以把写在里面的程序擦除掉了。由于这种存储器它的擦写过程是用紫外线，那么为了避免存储器里面的信息丢失掉，我们在每一次写好这个存取的信息以后，都要用一个黑色的挡光的不干胶把这个小窗子把它盖住，来防止信息的丢失。这种存储器比之前有了很大的进步，但是依然感觉还是挺麻烦的，于是呢，聪明的工程师们便发明了"电可擦写可编程只读存储器"，这种存储器的特点是不需要用紫外线照射就可以擦写到它们里面的内容，那么它是通过电信号把数据擦除或者写入到存储器里面了。

那么讲到这儿，不知道有朋友会好奇，既然这种 EEPROM 有这么多优点，断电以后还能保持，是不是我们可以用它来代替静态随机存储器 Static RAM 呢？答案自然是否定的了。那么具体什么原因呢？原因有很多种，其中最关键的一个原因，就是 EEPROM 这种存储器介质它的读写速度还是远远比不上 Static RAM 它的读写速度，那么我们是没有办法用电可擦写可编程只读存储器来代替 Static RAM。那么到这儿，我就把微控制器它存储单元里面三种不同的存储介质给大家介绍完毕了，分别是：Flash 闪存，它的作用主要是用来存储 Arduino 程序的；Static RAM 静态随机存储器，它主要是服务于程序变量的；还有 EEPROM，它的作用是可以存储需要断电仍旧能够保持住的程序变量。

那么这节课的内容到这里就结束了，下节课我们将一起来学习如何用 Arduino 来读和写 EEPROM，以及如何利用 Flash 闪存来存储我们程序内容里面不需要更改的一些静态的信息，从而达到让我们的 Arduino 在工作的时候它的内存以更加优化的形式来进行工作。好，这节课内容到这里就结束了，感谢您，我们下节课再见。

## 本节要点

- Arduino 开发板最核心的元件是 ATmega328 微控制器，它一方面执行我们上传的程序，另一方面内部设置有存储单元；掌握其存储结构与原理，能让程序运行得更高效稳定，也能实现以前做不到的新功能。
- 微控制器内置三种存储介质：Flash 闪存（相当于 U 盘使用的存储介质）、Static RAM 静态随机存储器、以及后面重点介绍的 EEPROM。
- Flash 与 Static RAM 的特点互补：Flash 价格低廉但读写速度相对较慢，Static RAM 价格较高但读写速度比闪存快得多；若只有 Flash，微控制器的运行速度会慢到难以接受，很多对时间要求高的功能也无法实现。
- 静态信息与动态信息的区分：静态信息在 Arduino 运行过程中不发生任何改变，例如编译上传后的 Arduino 程序，用 Flash 存储；动态信息在程序运行中经常变化，例如程序变量，用 Static RAM 存储。
- 两种介质的命名与所存信息内容无关，名字来自各自的工艺技术；Flash（"闪"）反而存静态信息，Static RAM（"文静"）反而存动态信息。
- 断电特性不同：Flash 断电后存储内容可以保持，Static RAM 断电后内容就丢失了。所以关掉开发板电源，程序不丢，但程序里的变量内容会被清空，下次上电后变量会随程序运行重新变化。
- 实际需求引出了 EEPROM（电可擦除可编程只读存储器）：希望某些变量在断电后仍能记住数值，例如智能灯希望每次开机都能记住用户设定的颜色和亮度，而不必重新设置。
- EEPROM 的进化脉络：存储器 → 只读存储器（只能读不能写，如 CD、DVD）→ 可编程只读存储器（施加电流固化程序，但只能写一次，写错即报废）→ 可擦写可编程只读存储器（芯片上有小窗户，用紫外线照射即可擦除，需用黑色不干胶挡光防止信息丢失）→ 电可擦写可编程只读存储器（用电信号擦除或写入数据，无需紫外线）。
- EEPROM 不能替代 Static RAM，最关键的原因是它的读写速度远远比不上 Static RAM；三种介质的用途可总结为：Flash 存 Arduino 程序，Static RAM 服务于程序变量，EEPROM 存储需要断电后仍保持的程序变量。下一节课将学习如何用 Arduino 读和写 EEPROM，以及如何用 Flash 存储程序中不需要更改的静态信息，从而优化 Arduino 的内存使用。
