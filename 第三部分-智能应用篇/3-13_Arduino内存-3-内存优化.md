## 正文

在之前的课程里，我给大家介绍过 Arduino UNO 开发板，它的核心元件 ATmega328 这个微控制器，它的存储单元一共有三种存储介质。这三种存储介质中的 Flash，它的大小是 32KB；SRAM 它的大小是两 KB；EEPROM 它的大小是一 KB。那么这节课我们的重点将放在 Flash 和 SRAM，我们将要学习如何来优化我们的程序，从而更好地让我们的 Arduino 开发板发挥出它的潜能。也就是说，这节课我们要学的是怎么把这两种存储介质用好、用巧，让有限的资源发挥出最大的作用、做出更多的事情来。

首先，由于 SRAM 它的大小远远小于 Flash，那么 SRAM 它这个资源就显得更加的珍贵，所以我们就先讲一讲如何来优化 SRAM。我们知道，当我们要用串口监视器输出一段文字的时候，我们可以调用 `Serial.print()` 或者 `Serial.println()` 这条指令，然后把我们需要输出的这段文字用双引号括起来。这个用双引号括起来的这段文字，它的学名叫做字符串。还记得我之前给大家说过，羊肉串成一串叫羊肉串，这个呢是字符串成一串了，所以它们叫字符串。那么当 Arduino 在运行的过程中，它会把这串字符串当做一个程序变量一样，把它存放到 SRAM 里面来进行处理。我们之前讲过，SRAM 它的特长是处理动态信息，那么我们这串字符串在整个程序运行中它是不会发生变化的，把一个不会变化的信息放到 SRAM 里面来处理，这个是挺浪费 SRAM 的。可能有的朋友已经猜到了，我们是不是可以把它放到 Flash 里面？因为 Flash 它本身就是用来存放静态信息的，没错，我们就把这段程序稍加修改就能达到这个目的了。

您现在在屏幕上看到的这两条指令，对于 Arduino 运行来说，它的运行结果是完全一样的，都是通过串口监视器显示出这么一排字符。我们只需要通过一个大写的 `F()` 再通过一对小括号，把输出的这段字符串把它括起来就可以了，那么 Arduino 在运行下面这条指令的时候，它将不会把这个字符串放在 SRAM 里面来处理，而是把它只存放在 Flash 里面，这样的话就大大地节约了 SRAM 的资源。您可千万别小看这个程序的修改，因为我们在调试一段程序代码的时候，经常会大量地用到这种串口监视器的输出，那么通过这种方法，也就是通过一个大写的 `F()` 加上一对小括号这种方法，是可以大大地优化我们的 SRAM 利用，也可以更好地把 Flash 利用起来。那么这个可以说是我们用来优化 SRAM 的第一种方法。而且这个方法使用起来非常简单，只是多敲几个字符，几乎不增加任何负担。

那么下面我们来介绍我们优化 SRAM 的第二种方法。请大家看，在屏幕上您看到这段程序，它的作用是建立了一个整数型的常量。那么当 Arduino 在运行过程中，它会把这个常量放到 SRAM 里面来进行处理。我们知道常量它在整个程序运行中是不发生任何改变的，换句话说，这个常量是一种静态信息，对于 SRAM 它来存放静态信息又是一种浪费。同样的，我们要把静态信息放到适合存放静态信息的哪里去呢？自然是 Flash 里面了。那么我们是如何做到的呢？请您看屏幕，我们只要在建立常量的时候增加一串大写字母，请看这个字符串的内容是什么呢？`PROGMEM`，P、R、O、G 就是 program 程序的前四个字母，M、E、M 这是内存也就是 memory 的前三个字母，那么通过增加这么一串字符，我们就可以让 Arduino 在运行程序的时候不再把这个常量放到 SRAM 里面，而是它将会放到 Flash 里面去，从而达到了优化 SRAM 以及更合理利用 Flash 这个目的。

刚才说的这两种方法，都是在 Arduino 的运行当中把 SRAM 里面的静态信息把它放到 Flash 里面去，从而用 Flash 来分担 SRAM 的压力。接下来，我们要对存放在 SRAM 里面的变量对它来做一个文章了。您现在在屏幕上看到的这段程序代码，它是不会让 Arduino 完成任何工作的，那么这段代码的意义就是为了向您展示 Arduino 在处理全局变量以及局部变量的时候是如何来利用 SRAM 的。首先我们来简单地看一看这个程序代码的内容，在程序刚开始的时候建立了两个整数型的全局变量，一个它的名称叫 `globalVar1`，一个是 `globalVar2`；在接下来的 `setup()` 函数里面是空的，然后 Arduino 将进入 `loop()` 函数，在 `loop()` 函数里面的 Arduino 调用了两个函数，一个叫 `function1`，一个叫 `function2`，在这两个函数里面都各自建立了一个局部变量，除了这些，这两个函数也不做别的工作了。好，程序很简单，Arduino 在执行这段代码的时候也确实没做什么事，那么我们来看一看 Arduino 在建立这些变量的时候它如何利用这个 SRAM 的。我们先从全局变量说起。

在程序刚开始的时候，建立第一个全局变量的时候，Arduino 将会在它的 SRAM 里面开辟一块专属的空间，那这块空间一旦被 `globalVar1` 所占用了以后，其他的任何变量就不能再用了，这块空间是专属于 `globalVar1` 的。当 Arduino 在建立第二个全局变量的时候，它只能利用 SRAM 里面剩下的这一部分，那么它只能在剩余的这部分里面再开辟一个独立的空间，那么这部分独立的空间一旦被 `globalVar2` 所占用以后，其他的任何变量也不能再利用了。换句话说，全局变量它对于 SRAM 的占用是非常自私的，一旦被它占了，谁也别想用了。

好，那我们接着往下看，Arduino 进入 `loop()` 函数里面调用 `function1` 的时候，在 `function1` 里边是建立了一个局部变量，那么为了建立这个局部变量，Arduino 将会在剩余的 SRAM 的部分再开辟一个空间，那这部分空间是作为局部变量一也就是 `localVar1` 所使用的。但是请注意，与全局变量不同的是，当 Arduino 在执行完 `function1` 的程序内容以后，它会把所有 `function1` 里面的局部变量所占用的 SRAM 都释放出来，那么原来建立 `localVar1` 这个局部变量的这部分 SRAM 就可以再一次被利用了。这一点和全局变量形成了鲜明的对比，也正是我们后面优化内存的重要依据。换句话说，当 Arduino 执行 `function2`，也就调用函数二的时候，在这个里面的 Arduino 建立了第二个局部变量，那么当它建立这第二个局部变量的时候，它可以再次使用这部分刚刚建立 `localVar1` 的这部分 SRAM，也就是说对于局部变量来说，它们所使用的 SRAM 是一种共享的模式来使用的。同样的，当然，当 Arduino 完成了 `function2` 的程序内容以后，它会把函数二所建立的局部变量把这部分占用的 SRAM 把它释放出来，这样的话其他的局部变量也就可以共享这部分空余的 SRAM 了。那么这个也就引出了我们优化 SRAM 的第三种方法，对于可以共享 SRAM 的局部变量，以及对于独享 SRAM 的全局变量，我们更倾向于哪一种呢？当然我们是希望尽量多使用局部变量来代替全局变量，这样的话 SRAM 也会以更加优化的一种方式来被利用。好，这个也就我们第三种优化 SRAM 的方法。

但是讲到这儿，有一点我要跟你提醒一下，请看，在刚刚我讲解所使用的这个示意图里面的各个变量的大小，以及整体的 SRAM 的大小，这个尺寸是不成比例的，事实上我们的 SRAM 它是不单单只能存放这么几个整数型变量的。那么对于 Arduino UNO 这个开发板来说，它的 SRAM 到底能存放多少个整数型变量呢？要回答这个问题，我们就要弄清楚，对于整数型变量，它是要占用多大的 SRAM，那么这个问题的答案是两个字节，每一个整数型变量它都会占用两个字节的 SRAM。好，我们现在所说的是一个整数型的变量，那是不是所有的变量类型所占用的 SRAM 的大小都是相同的呢？当然不是了，不然的话也就不会涉及那么多种不同类型的变量了。好，请看，对于一个布尔型的变量，它所占用的 SRAM 大小就只有一个字节。我们知道 Arduino UNO 它的 SRAM 的大小是两 KB，好，那么对于两 KB 这个 SRAM 理论上来说，它能存放的布尔型的变量是 2048 个，那么对于存放整数型的变量呢，它只能存放 1024 个。那么这个也就引出了我们第四种优化 SRAM 的方法，也就是说尽量要使用占用内存少的数据类型来写程序。因为在 SRAM 里面，节省下来的每一个字节，都可能意味着我们的程序能够多跑一会儿，或者能够多做一件事情。

好，关于如何写程序才能更加优化利用 SRAM 这部分知识，我要给大家介绍的就是这些了，下面我来给大家讲一讲如何写程序才能够更加优化地使用 Flash 闪存。我们知道 Flash 闪存它的主要功能之一就是存放我们所写的程序代码，那么自然而然，要想优化 Flash，最根本的方法自然就是如何优化我们的 Arduino 程序代码。那么优化 Arduino 程序最直接的方法，就是在写程序代码的时候尽量保持简洁，能够用一句程序解决的问题，千万不要用一句半。我希望我们在写程序的时候，脑海中经常能记住这句话，也就是 simplicity is the ultimate sophistication。虽然讲这句话的人并不是一个很会写程序代码的人，但是他所留给我们的财富还确实值得我们后人好好品味的。

## 本节要点

- Arduino UNO 的 ATmega328 有三种存储介质：Flash 32KB、SRAM 2KB、EEPROM 1KB。SRAM 容量最小、最珍贵，因此内存优化的重点在 SRAM。
- 优化 SRAM 的第一种方法：把 `Serial.print()` / `Serial.println()` 输出的字符串用大写 `F()` 包起来，让它只存放在 Flash 里，而不是被当作变量放到 SRAM 里。
- 优化 SRAM 的第二种方法：给常量加上 `PROGMEM` 修饰，让常量存放在 Flash 而不是 SRAM 中，用 Flash 来分担 SRAM 的压力。
- 全局变量会独享 SRAM 空间，一旦占用其他变量就无法使用；局部变量则在函数执行完以后释放空间，可以被其他局部变量共享，所以应尽量用局部变量代替全局变量，这是第三种优化方法。
- 整数型变量占两个字节，布尔型变量只占一个字节；2KB 的 SRAM 理论上可存 1024 个整数型变量或 2048 个布尔型变量，因此应尽量选择占用内存少的数据类型，这是第四种优化方法。
- 数据类型占用的字节数与数值范围可到太极创客网站查询：布尔型 1 个字节，数值为 true 和 false；整数型 2 个字节，范围为 -32768 到 32767。该表基于 AVR 八位微控制器（UNO、NANO、MEGA），对 32 位开发板（如 Due）不再适用，表格备注栏中有相应说明。
- 优化 Flash 的根本方法是让程序代码保持简洁，能用一句解决的问题不要用一句半；同时要及时删除无用的库、无用的变量、无用的函数以及无用的零散代码，尤其注意无用库会把辅助代码一起复制进 Flash。
- 实例对比：环保小夜灯示例程序优化前 Flash 占用 10%、SRAM 占用 9%，优化后 Flash 占用 5%、SRAM 占用 0%。优化手段即用 `F()` 包裹串口输出字符串、把亮度参数改为带 `PROGMEM` 的常量、把控制 RGB LED 亮度的变量由 int 改为 byte。
