剩下两个引脚就比较容易理解了，GND 就是 GND，VCC 就是给模块供电使用的，它的范围是 3.6 伏特到 6 伏特，换句话说我们可以用 Arduino 上面这个 5 伏特这个引脚给模块进行供电。那么对于我们的 Arduino UNO 开发板上来说，它的 TX 和 RX 分别对应的数字输入输出引脚的引脚 1 和引脚 0，您可以看看您的开发板上面，这两个引脚之间肯定是标注出来了，next 的 TX 那个是 RX。

下面我们再来看这个模块它的名称里的"透传"这个概念。所谓透传，就是透明传输这么一个概念的缩写，那么它代表的意思是：在数据传输过程中，数据是不发生任何形式的改变的，这个传输过程就好像是透明的一样，数据原封不动的从发送者传到接收者。换句话说，我们这个 HC-06 无线蓝牙这个模块，它只是一个数据的搬运工。

好，大家现在屏幕上看到的是 HC-06 这个模块它四个引脚的说明。我刚才说过，Arduino 的串口通讯高电平是 5 伏特，那么 HC-06 它的串口通讯高电平是 3.3 伏特。这样的结果，对于 HC-06 发送数据给 Arduino 的时候，它对应的是一个低电压到高电压的过程，在这种情况下没有任何问题。那么反过来，假如我们用 Arduino 的 TX 引脚发送数据给 HC-06 的 RX 这个引脚，这个时候我们相当于给一个只允许接收 3.3 伏特的一个数据引脚施加了一个高于它允许范围的值——5 伏特，那这种情况下，如果我们短时间使用问题不大，但如果长时间地、反复地使用的话，可能会把 HC-06 模块给烧坏了。所以呢，我们就要在 HC-06 它这个 RX 引脚上面接一个**分压电路**，那这个分压电路的作用就是要把 Arduino 发来的这个比较高的电压信号降低到 HC-06 能够接收的这个电压范围内。

下面我们来看 HC-06 是如何跟 Arduino 开发板进行连接的。我们先来看 HC-06 的 TX 引脚，它的连接就是通过一根导线把这两个引脚连在一起；另外一个 RX 引脚，请看它是通过分压电路和 Arduino 的 TX 引脚进行连接的。在这里请大家务必要注意一点：在我们使用 Arduino UNO 这款开发板，它的引脚 0 和引脚 1 这两个引脚一旦跟外界的任何设备通过导线连接到一起以后，我们如果再想要通过电脑里的 Arduino IDE 通过数据线上传程序给开发板，这个上传过程是肯定要失败的，也就是 Arduino 开发板的引脚 0、引脚 1 就不能给它上传程序了。要想给它上传程序怎么办呢？就要把这两个导线尽量把它移除掉，然后才能够给开发板再上传新的程序。造成这个问题的原因，就是 Arduino 开发板它在接收我们电脑上传给它的程序时候用的就是引脚 0 和引脚 1，也就是 TX 和 RX，那这两个引脚如果一旦接了别的设备，自然而然 Arduino UNO 这个开发板它就无法正常地来接受上传给它的程序了。所以这个过程只影响上传程序，它们是不会影响到 Arduino 的运行的。

## 本节要点

- HC-06 全称是"无线蓝牙串口透传模块"：串口指用 TX/RX 两根数据线收发数据，透传指数据传输过程中不对数据做任何改变，模块只充当数据的搬运工。
- HC-06 的串口通讯高电平是 3.3V，而 Arduino 的高电平是 5V。HC-06 发数据给 Arduino 没问题；Arduino 的 TX 直接接 HC-06 的 RX 会因电压过高、长时间使用而烧坏模块。
- 因此需要在 HC-06 的 RX 引脚上加分压电路：由两个电阻构成，5V 经分压后 RX 端约得到 3.2V（电流约 0.16mA），满足模块工作要求。
- Arduino UNO 上传程序必须使用引脚 0、引脚 1（即 TX、RX），所以上传时要先断开与 HC-06 的连线，上传完成后再接上；这只会影响上传，不影响运行。
- 接线要点：HC-06 的 TX 接 Arduino 的 RX、RX 经分压电路接 Arduino 的 TX、GND 共地，VCC 可接 Arduino 的 5V 引脚供电（模块供电范围 3.6V～6V）。
- 演示程序用字符变量 `serial data`（正文中为 `serialData`）保存 `Serial.read()` 读到的字符：收到字符 1 时用 `digitalWrite()` 点亮引脚 11 的 LED，否则熄灭 LED，并通过串口回送相应文字。
- Arduino Bluetooth Controller 有四种工作模式，本例用了 switch mode（开关模式）、terminal mode（终端模式）和 dimmer mode（调光模式）三种。
- 首次配对 PIN 默认是 1234；未连接时 HC-06 红灯连续闪烁，连接成功后红灯常亮。
- 硬件串口接 HC-06 存在两个问题：一是上传程序必须拔掉引脚 0、1 上的连线，很麻烦；二是只有一个串口，只能跟一台设备通讯——这为下一节的软件串口做铺垫。
